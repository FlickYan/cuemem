# Demo guide: a shopping assistant that remembers (about 3 minutes)

English · [简体中文](README.md)

The demo is Cue, the shopping assistant built in N8, working for CueMart, a fictional sports store. CueMart has 24 products, with images generated by qwen-image-3.0. The user, Maya, chatted with Cue once in August and once in September. The demo is her third chat, on October 10, and shows:

- **Cross-session recall and knowledge updates**: running-shoe size 40 (her general size stays 39), budget $120 → $180.
- **Finding look-alikes of a shared photo.** The August photo is recalled from memory, and the original is shown to the model again.
- **The memory trace of every turn**: why the controller chose what it chose, what went into the context, and which memories the answer cites.
- **Forgetting.** Deleting a fact also deletes the replies that repeated it, whether they cited it or only restated it in passing.

![The demo as an animated GIF](../docs/assets/demo.gif)

## Setup (once)

```bash
uv sync
uv run cuemem configure          # enter the QwenCloud key (the demo uses Qwen only, no DeepSeek)
uv run cuemem demo demo/shop/script.json --fresh --until 2
```

The last command clears the memory space `shop-demo` and replays the first two chats from the script (August 28 and September 12), consolidating after each. It takes about 2 minutes and costs about $0.02. **Run it again before every recording**, to clear memory left over from the previous live chat.

```bash
uv run cuemem serve              # open http://127.0.0.1:7860/
```

## Walkthrough

| Time | Do | Say |
|---|---|---|
| 0:00 | Open the UI; set "Session date" to `2026-10-10 10:00`; click New session | The memory already holds the August and September chats; dates are simulated |
| 0:15 | Send `Hi Cue, I'm back!` | Cue knows her name, her marathon plan and the shoes she liked. On the right: the controller's choice and the profile lines cited |
| 0:40 | Send `What size running shoes do I wear now?` | EU 40, and why it changed from 39 in September. Both facts stay current in memory: since N11, reconciliation treats "EU 40 for running shoes" as a narrower scope than "EU 39 shoes" and adds it instead of replacing the general size (D-053). The budget at 1:40 is the example of a superseded fact |
| 1:05 | Send `Can you find shoes that look like the pair I showed you in August?` | The trace shows the August photo, recalled from memory, with the original shown to the model ("original photo shown to the model"). Cue then searches the catalogue by image; product images appear under the answer |
| 1:40 | Send `How has my shoe budget changed since we first talked?` | $120 → $180, citing the superseded fact and the new one. If the controller picked L0, the trace shows the model calling `memory_search` itself: the controller recalls first and the model may search more. You can also switch Recall to l2 under Memory controller settings to show deep recall's plan and follow-up retrieval |
| 2:10 | Open the Memory tab | Profile; the fact timeline with the superseded budget and what replaced it; the entity graph; the photo gallery |
| 2:30 | Forget a → fact → pick "…Ana who turns 30 on October 3rd." → Forget | Three things are deleted. First, the exchange the fact came from. Second, any later reply that cited it. Third, replies that only restated it without citing: for example, an earlier reply saying "her birthday is October 3, order soon", or today's greeting if it mentioned the birthday. Only those replies go: what the user said in the same exchange stays. The result line counts them ("including N that restated it without citing"). Facts and profile are rebuilt from what remains |
| 2:50 | Back on Chat, send `When is my sister's birthday?` | Cue does not know. The chat history on screen remains, but Cue's context and memory no longer have it |

Also worth pointing out:

- In the trace panel, each level's "expected accuracy" and its score after the cost penalty. A larger λ saves more.
- The context budget bar:
  - the system prompt, the profile and this chat's raw turns form a stable prefix, so the provider's prefix cache keeps hitting;
  - recalled memories are recomputed every turn and go last;
  - the Usage line shows how much input came from the prefix cache.
- Two biases of the controller in this domain (see the [N8 results](../docs/results/n8-agent/README.md), in Chinese):
  - with photos in memory it almost always attaches them;
  - "how did my budget change" may be judged as not needing memory.

## Answers vary

The model's answers differ slightly from run to run, and the controller's choices change with the memory's content. The script's automatic checks look at key content only:

```bash
uv run cuemem demo demo/shop/script.json --fresh   # three chats plus forgetting, 14 checks
```

A full replay ends with forgetting, which also clears the answer cache of the sessions it touches (since N11 the cache is scoped per session, so other sessions keep theirs; D-054). Afterwards, run `--until 2` again to restore the pre-demo state.

To re-record the GIF above, keep `cuemem serve` running on a freshly built demo memory, then run `uv run --with playwright python scripts/record_demo.py`. It uses your local Google Chrome.

| `shop/catalog.json` | Product catalogue (name, price, colour, materials, sizes, tags, description) and the prompts used to generate the images |

| `shop/script.json` | The script: three chats and the checks for each message |
