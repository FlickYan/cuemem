## 配对比较（基准 B4，同一批题）

`uv run python scripts/paired_compare.py runs/eval/dev100-n4 --base B4 --others B1,B2,B2F,...`

| 方法 | dev100：B4 对、它错 | B4 错、它对 | 符号检验 p | LoCoMo：B4 对、它错 | B4 错、它对 | 符号检验 p |
|---|---|---|---|---|---|---|
| B1 全上下文 | 16 | 5 | 0.027 | — | — | — |
| B2 朴素检索 | 9 | 2 | 0.065 | 56 | 20 | <0.001 |
| B2F 朴素检索 + 事实记忆 | 6 | 3 | 0.51 | 37 | 13 | 0.001 |
| B4-k10：固定取 10 轮 | 4 | 3 | 1.00 | 41 | 11 | <0.001 |
| B4-k5：固定取 5 轮 | 2 | 1 | 1.00 | — | — | — |
| B4-b2k：预算 2k tokens | 8 | 3 | 0.23 | 4 | 6 | 0.75 |
| B4-notime：不做时间加分 | 0 | 1 | 1.00 | 1 | 1 | 1.00 |
| B4-norel：不标相对时间 | 5 | 1 | 0.22 | 11 | 11 | 1.00 |
| B4-nobm25：去掉 BM25 | 5 | 3 | 0.73 | 10 | 15 | 0.42 |
| ORACLE 只给证据会话 | 6 | 6 | 1.00 | 24 | 34 | 0.24 |

- dev100 已接近饱和：B4 与 ORACLE 同为 83%，与 B2、B2F 的差异都不显著。B4 的价值在 LoCoMo 上看得更清楚：显著优于 B2（75.6%）与 B2F（78.7%），与 ORACLE（87.5%）的差异不显著。
- LoCoMo 的提升集中在多跳题：B2 50%、B2F 62%、B4 81%（ORACLE 74%，它只给证据会话，没有事实与核心记忆）。
- 最大的杠杆是按 token 预算打包（D-029）。LongMemEval 的一轮约 490 tokens，4k 预算平均装 8.2 轮。LoCoMo 的一轮只有一句话（约 40 tokens），按预算会装满 40 轮的上限。固定取 10 轮让 LoCoMo 的上下文少了四分之三：B4-k10 只有 77.1%，比 B4 低 7.8 个点（p < 0.001）。注意这一项是看过 LoCoMo 的结果后加的（text-embedding-v4 时固定 10 轮的 B4 不如 B2F），LoCoMo 对它不是独立检验（D-029）。
- 时间区间加分、BM25 在两个数据集上都没有显著影响（D-026、D-027）。去掉"距提问几天"的标注，dev100 少 4 题（p = 0.22），LoCoMo 持平。

## 纯检索指标（dev100，94 道非拒答题，固定前 10 轮，不调用 reader）

`uv run python scripts/tune_l1.py --split dev100`，约 30 秒，零 LLM 成本。

| 配置 | 发言召回（任一） | 发言召回（全部） | 会话召回（全部） | 发言 NDCG |
|---|---|---|---|---|
| B2 dense 轮 | 93.6% | 87.3% | 91.5% | 71.9% |
| B2F 事实增强键 | 100.0% | 96.8% | 99.3% | 83.0% |
| 按类型 RRF + BM25（对照，D-025） | 100.0% | 94.4% | 97.8% | 75.3% |
| L1：模态内取最大 + BM25×0.5 | 100.0% | 92.9% | 97.4% | 79.5% |
| L1，不用稀疏路 | 100.0% | 96.8% | 99.3% | 83.0% |
| L1 + 时间区间（B4 的排序） | 100.0% | 92.9% | 96.0% | 80.6% |
| L1 + 新旧顺序 | 100.0% | 93.0% | 97.4% | 78.2% |
| L1 + 会话摘要先验 | 100.0% | 92.9% | 96.1% | 78.0% |

- "L1，不用稀疏路"与 B2F 的排序完全一致，这可以作为融合实现的正确性校验（D-025）。
- 按类型 RRF 把"助手说过"类题的 NDCG 从 95.5% 拉到 51.5%：助手说的内容没有对应的事实，一条余弦很高的直接命中会被几条名次中等的事实键叠加挤下去。
- 换用 qwen3.7 后，BM25 在纯检索上不再有帮助：NDCG 79.5% 对不用稀疏路的 83.0%，多会话与时间题下降最多。text-embedding-v4 时代 BM25 是有用的（D-026）。默认配置保持 N4 评测时的设置，N5 结合重排再复议。

## L1 检索延迟（dev100，94 题，串行，查询向量化不走缓存）

`uv run python scripts/tune_l1.py --split dev100 --latency --workers 1`

| 配置 | 总计 p50 / p95 | 其中查询向量化 p50 / p95 | 本地检索与融合 p50 / p95 |
|---|---|---|---|
| B4 的检索（L1 + BM25 + 时间区间） | 99 / 132 ms | 81 / 113 ms | 18 / 20 ms |
| L1，不用稀疏路 | 95 / 108 ms | 81 / 93 ms | 15 / 17 ms |
| 第一次查询（现建 BM25 索引） | 124 / 156 ms | 81 / 108 ms | 43 / 72 ms |

验收目标是 p95 ≤ 300 ms（含一次查询向量化），已达到。延迟主要花在向量接口的网络往返上，本地检索、融合与打包不到 25 ms。BM25 索引按空间缓存，只在写入新内容后重建（LongMemEval 一个空间约 250 轮、230 条事实、48 段会话摘要，现建约 25 ms）。

## 向量模型：text-embedding-v4 → qwen3.7-text-embedding

同一份代码、同一批题，只换向量模型（`runs/eval/dev100-n4-v4`、`locomo-3conv-n4-v4` 对 `dev100-n4`、`locomo-3conv-n4`）：

| 方法 | dev100 v4 | dev100 qwen3.7 | LoCoMo v4 | LoCoMo qwen3.7 |
|---|---|---|---|---|
| B2 朴素检索 | 65% | 76% | 71.2% | 75.6% |
| B2F 朴素检索 + 事实记忆 | 80% | 80% | 77.7% | 78.7% |
| B4，固定取 10 轮 | 80% | 82% | 76.1% | 77.1% |

换向量模型让朴素检索提升了 11 个点，超过 N4 里任何一项检索技巧。B2F 几乎不变，说明事实增强键已经补上了弱向量模型的大部分召回损失。30 题的纯检索对比见 [D-014](../../decisions.md)。

## 复现

```bash
uv run cuemem eval run --split dev100 --name dev100-n4 \
  --methods B0,B1,B2,B2F,B4,B4-k10,B4-k5,B4-b2k,B4-notime,B4-norel,B4-nobm25,ORACLE
uv run cuemem eval run --dataset locomo --split all --limit 385 --name locomo-3conv-n4 \
  --methods B2,B2F,B4,B4-k10,B4-b2k,B4-notime,B4-norel,B4-nobm25,ORACLE
```

记忆空间落盘复用（D-028）：首次需要用 qwen3.7 重新向量化（dev100 约 720 万 tokens，$0.50）；巩固结果由 LLM 缓存命中。DeepSeek 的调用默认避开高峰时段（D-024）。N4 合计花费约 $2.9（计入错峰折扣；不计折扣约 $3.9），没有一次 DeepSeek 调用落在高峰时段。
