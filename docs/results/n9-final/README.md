# N9 结果：测试集上的最终评测

测试集只用这一次，方法、控制器（N7 导出的模型，λ = 30）、检索配置与提示词都在看测试集之前冻结（D-048）。

- **数据**：LongMemEval test400、LoCoMo 后 7 段对话（非对抗题 1,155 道）、MemLens 官方 195 题（32K 与 128K），以及测试集版混合流（1,750 道记忆题 + 3,500 条与记忆无关的查询）。
- **回答与判分**：主回答模型 deepseek-flash，判分 qwen3.8-max。另有三个回答模型在分层子集上复测（D-049）。
- **成本**：名义成本（D-010）。

完整的表格在 [tables.md](tables.md)（由脚本生成），原始数字在 [results.json](results.json)，人工错误标注在 [error_labels.json](error_labels.json)。综合起来的结论与讨论见[技术报告](../../report.md)。

## 结论

1. **记忆系统比全上下文又准又便宜，长历史上差距更大。**
   - **LongMemEval**：L1 快速召回 90.5%，每千题 $1.60；全上下文 73.0%，每千题 $31.88。准确率高 17.5 个点（+84 / −14），成本约为 1/20。
   - **LoCoMo**（每段对话约 2 万 tokens，全上下文本身就不长）：L1 比全上下文低 2.3 个点（p = 0.038），L2 高 2.5 个点（p = 0.021），成本不到一半。
   - **MemLens**：全上下文（图片原位插入）32K 是 51.8%、128K 是 46.2%；L2 + 再感知分别是 65.6%、65.1%，不随历史变长而下降。
2. **写入路径是最大的单项收益。** 朴素检索换上写入路径的产出（带有效期的事实、事实增强的检索键、画像），LongMemEval 82.0% → 91.0%（+53 / −17，p < 0.001），主要在多会话题（+16.5 个点）与时间题（+16.7 个点）。在这之上，L1 的检索改进在 LongMemEval 上没有再挣到（90.5% 对 91.0%），LoCoMo 上比朴素检索高 11.5 个点（+168 / −36）。
3. **L2 对 L1：LoCoMo 上四类题全部显著，其他数据集方向一致。**
   - **LoCoMo**：+4.8 个点（+76 / −20，p < 0.001）。N5 没达到的"分题型显著"在这里达到了：多跳、开放推断、时间、单跳四类的 p 值都小于 0.05。
   - **LongMemEval**：+2.7 个点（p = 0.071）。
   - **MemLens**（都带再感知）：32K +2.5 个点（n.s.），128K +9.7 个点（p < 0.001）。
4. **冻结的控制器在测试集上复现了开发集的估计，结论也没变。**
   - 合并的记忆题准确率：B6 81.2% → 81.6%（开发集 → 测试集）。
   - 混合流里比"总是检索"便宜 45% → 41%，准确率不降。
   - 测试集上 B6 对总是 L1 是 +60 / −37（p = 0.025），对总是 L2 是 +15 / −64（p < 0.001）。
   - 价值仍在"要不要想起"，不在"L1 还是 L2"（H2 的一半成立、一半不成立，与 N7 相同）。
5. **控制器在 MemLens 上有一个设计缺陷。**
   - 有图时，控制器把"看图的增益"加到 L1、L2 的预测成功率上，再截断到 1.0。
   - 增益一大，两档都被截成 1.0，排序信息丢了，代价项就总选便宜的 L1。
   - 32K 上 B6 有 25% 的题是在两档都被截成 1.0 时选了 L1 + 看图。B6 输给总是 L2 的 13 道题里，有 6 道出在这里；另有 5 道是门控把记忆题判成了与记忆无关，多是指代已分享图片的问题。
6. **模型自主检索（B3）读文字很强，到了图片上就失灵。**
   - 文字：LoCoMo 上它是最好的方法（85.5%），LongMemEval 92.0%。
   - 图片：MemLens 上只有 46.7%。它的检索工具只返回文字，信息抽取题 24.6%，并且 58 道错题是误拒答。
   - "控制器先选、模型兜底"（B6a）三个数据集都不差（90.0% / 84.4% / 61.5%），但最贵（每千题 $4.21–8.10）。
7. **H3 仍不成立。** 换三个回答模型，B3 的波动不比控制器大；最小的模型上 B3 也没有明显吃亏。另一个发现是：控制器的"各档准确率"表是按主回答模型标定的，小模型上 L1 比 L2 差得多（LongMemEval 80.8% 对 89.9%），控制器不知道，照样大量选 L1（B6 对 L2 0 / −7，p = 0.016）。大模型 deepseek-v4-pro 一档因 DeepSeek 账户余额不足没有跑。
8. **H4 未得到支持。** 知识更新题上，完整版、"只给当前事实"、"事实不标有效期"三种写法都是 96.5%（55 / 57）：原始对话仍在上下文里，模型自己就能分辨新旧。
9. **错题里"检索没取到"的很少，多的是控制器选错档、计数漏数和数据集本身的问题**（详见下文）。
10. **可复现。** B6 的真实运行与冻结模型的离线重放逐题一致：400 / 400、1,155 / 1,155、195 / 195 × 2。

## 冻结的控制器：开发集的估计在测试集上复现了

| 策略 | 记忆题：开发集 585 题（交叉拟合） | 记忆题：测试集 1,750 题（冻结） | 混合流每千条成本（记忆题 20%）：开发 → 测试 | 误召回：开发 → 测试 | 漏召回：开发 → 测试 |
|---|---|---|---|---|---|
| 总是 L1 | 80.5% / $1.57 | 80.3% / $1.53 | $1.57 → $1.53 | 100% → 100% | 0 → 0 |
| 总是 L2 | 85.3% / $3.46 | 84.4% / $3.42 | $3.46 → $3.42 | 100% → 100% | 0 → 0 |
| B6r 规则版 | 82.6% / $2.01 | 81.4% / $2.07 | $1.92 → $1.95 | 100% → 100% | 0 → 0 |
| B6z 零样本 LLM 路由 | 80.7% / $2.15 | 80.3% / $2.23 | $0.72 → $0.74 | 0.4% → 0.8% | 5.3% → 3.0% |
| B6h 拿不准时问 LLM | 80.2% / $2.21 | 81.3% / $2.41 | $0.80 → $0.85 | 10.3% → 11.0% | 3.9% → 1.8% |
| **B6（λ = 30）** | **81.2% / $2.14** | **81.6% / $2.36** | **$0.87 → $0.90** | 19.2% → 17.3% | 2.4% → 1.1% |

- **门控**：区分记忆题与无关查询的 AUC 是 0.990（开发集 0.983）。按数据集分：LoCoMo 0.997、LongMemEval 0.985、MemLens 32K 0.929。
- **探针延迟**：p50 163–487 ms，p95 257–833 ms（MemLens 128K 的空间最大）。
- **分数据集，B6 都夹在总是 L1 与总是 L2 之间**：
  - LongMemEval：与总是 L1 打平（+10 / −10），成本高 51%；规则版 B6r 92.5%，比它好（+12 / −4，p = 0.077）。
  - LoCoMo：比 L1 好（+42 / −13，p < 0.001），也比 B6r 好（+34 / −16，p = 0.015）。
  - MemLens：两个尺寸都显著低于总是 L2。
- **它输给总是 L2 的地方**（按 B6 选的档）：
  - LongMemEval：L0 上 6 道，L1 上 11 道，L1 上也赢回 6 道；
  - LoCoMo：L0 上 1 道，L1 上 33 道，赢回 7 道；
  - MemLens 32K：L0 上 5 道，L1 上 8 道，赢回 2 道。
- **"L1 + 先记笔记"仍然很划算**：LongMemEval 91.8% / $1.86，LoCoMo 82.8% / $1.70，都比 B6 准、也比 B6 便宜（两个数据集合并 +56 / −44，p = 0.27）。

## 错误分析

自动归因覆盖全部错题。人工从 B6 的错题里按题型分层抽 40 道（LongMemEval 只错 38 道，全看）逐题标注，定义见 `scripts/n9_errors.py`。"控制器选错档"的口径：选了 L0 的记忆题；或选了 L1、换 L2 就能答对（反过来不算）；或该附原图却没附。

| 人工标注 | LongMemEval（38 / 38） | LoCoMo（40 / 206） | MemLens 32K（40 / 78） |
|---|---|---|---|
| 控制器选错档 | **16** | 3 | **9** |
| 计数 / 求和 / 列举 | 9 | **10** | 6 |
| 标准答案有误或推不出 | 3 | **10** | 2 |
| 日期推算 | 3 | 1 | 2 |
| 用了过时的版本 | 2 | — | 1 |
| 误拒答 | 2 | 2 | 5 |
| 判分过严 | 2 | 4 | 5 |
| 证据没进上下文 | 1 | 5 | — |
| 推理或理解 | — | 5 | 2 |
| 看错图 | — | — | 8 |

- **LongMemEval 上最大的一类是选错档（16 / 38）。**
  - 6 道是门控把记忆题放到了 L0，换 L1 全部答对。这些问题没有"我上次说过"之类的线索，例如"我们公司的领导岗位里女性占百分之几？"。
  - 10 道是选了 L1、L2 能答对：多会话的计数、时间推算（L2 的笔记会先把日期差算出来），还有 3 道偏好题。
- **计数与列举是三个数据集共同的难点。** 证据都取到了，模型漏数或重复数：一年里去过几场婚礼答成 5 场（应为 3 场），去过的博物馆漏掉第一家。
- **LoCoMo 的标准答案有不少问题（10 / 40）。** 年份写错（"2024 年 1 月 10 日的会话里说'昨天'"，标准答案是 2023 年 1 月 9 日）、天数算错（7 月 11 日到 20 日，标准答案 19 天）、把对方的话算到本人头上、答案只在图片里。7 道时间题里有 5 道属于这类。这些题没有剔除，数字照实报告。
- **真正"检索没取到"的很少**：LongMemEval 1 道，LoCoMo 5 道。
- **记忆的有效期标错了一次。** 对账把三条范围不同的起床时间串成了一条新旧链："工作日 6 点半" → "每天 7 点半" → "周五 6 点"。问"周五比其他工作日早起多久"时，模型以为"工作日 6 点半"已经作废，给不出确定的答案。

## 测试集上的诊断：值得以后改、但这次不改的地方

测试集只用一次，下面这些问题在本项目里只记录、不回头调（D-048）。

1. **看图增益改成在对数几率上相加**，L1 + 看图与 L2 + 看图就不会同时饱和。
2. **门控对"指代已分享图片"、没有第一人称线索的问题加少量标注**（N7 里 20 条目标数据就能补回 LoCoMo 的迁移）。
3. **"各档准确率"表随回答模型重新标定。**
4. **L1 默认先记笔记**：LoCoMo 上 +3.1 个点（+49 / −13，p < 0.001），LongMemEval 上 +1.3 个点（n.s.），成本 +16–18%。

## 花费

N9 合计（按 API 账单口径：扣除供应商缓存、计入 DeepSeek 错峰半价）约 **$48.3**，名义 $86.5：

- DeepSeek 回答 $18.4；
- 通义（构建、L2 的规划与检查、判分、两个 qwen 回答模型、零样本路由）$27.3；
- 向量 $2.6。

DeepSeek 的调用全部在非高峰时段。中途 DeepSeek 余额用完过一次，充值后续跑。失败的请求不进缓存，续跑与一次跑完等价。

DeepSeek 账户当天实际扣款 ¥122.71。按账本里的 token 数核算（每百万 tokens：未命中 ¥2、命中 ¥0.04、输出 ¥8，错峰半价），结果一分不差。

- **91% 的钱花在没命中缓存的输入上。**
- **最大的一项是 LongMemEval 的全上下文基线（¥42，约三分之一）。** 每道题带着自己约 10.6 万 tokens 的历史、只问一次，题与题之间没有共同的前缀，缓存命中率只有 1%。对比 LoCoMo 的全上下文：同一段对话的题共用一段历史，命中率 99%。
- **其余主要是各种检索方法的回答。** 每道题检索到的记忆各不相同，只有开头的固定说明能命中缓存。
