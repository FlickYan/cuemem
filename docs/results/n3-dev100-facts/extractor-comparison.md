# 抽取模型对比：qwen3.8-flash vs deepseek-flash

- 日期：2026-10-12 · 脚本：`scripts/compare_extractors.py`（`--questions 30 --seed 0`）
- 样本：从开发集 dev100 按题型分层抽 30 道"答案是一个具体信息"的题（单会话用户信息、偏好、知识更新），取它们的 42 个证据会话，再随机加 30 个非证据会话作为干扰；共 72 个会话。不使用 test400。
- 两个模型用同一份抽取提示词（`write/extract.py`，助手回复保留开头 600 字符），都关闭思考模式，各自并发 12。

| 指标 | qwen3.8-flash | deepseek-flash | 含义 |
|---|---|---|---|
| 证据发言覆盖 | 100% | 100% | 标注为证据的发言至少被一条事实引用 |
| 答案实词召回 | 97.8% | 97.8% | 标准答案的实词出现在证据会话抽出的事实里（23 道短答案题的平均） |
| 每个证据会话的事实数 | 8.8 | 9.0 | |
| 每个干扰会话的事实数 | 4.4 | 5.1 | 越少说明越不容易记下琐碎内容 |
| 带日期的事实比例 | 29% | 42% | 抽查：两者的相对日期换算都基本正确；deepseek 更常把会话日期标给计划类事实 |
| JSON 重试 / 引用不存在的轮次 | 0 / 0 | 0 / 0 | |
| 输入 / 输出 tokens | 178,197 / 75,586 | 176,521 / 71,244 | |
| 每会话名义成本 | **$0.00086** | $0.00192 | deepseek 约贵 2.2 倍 |
| 延迟 p50 / p95 | 20.8 / 38.0 秒 | **5.5 / 8.1 秒** | deepseek 约快 4 倍（QwenCloud 上 qwen3.8-flash 输出约 50 tokens/秒） |

**结论（D-018）**：自动指标上两者质量相当；巩固在后台异步执行，对延迟不敏感，而抽取是写入成本的大头，所以默认用更便宜的 qwen3.8-flash。需要快速批量导入时，可以用 `CUEMEM_ROLES__EXTRACTOR__MODEL=deepseek-flash` 切换。

**局限**：答案实词召回只检查"答案出现在事实里"，不检查事实是否把细节写错；样本只有 72 个会话。更可靠的比较是端到端：用两种抽取分别跑 B2F 并判分，成本约为 dev100 抽取成本的 3 倍，留到需要时再做。
