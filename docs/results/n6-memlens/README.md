| **B4-see** B4-mm + 再感知 3 张原图 | **63.1%** | 55.9% | $0.0020 | 6,412 / 6,320 |
| B4-see-novis：去掉以文搜图 | 62.6% | 57.4% | $0.0018 | 5,902 / 5,894 |

| 比较 | 32K | 128K |
|---|---|---|
| B4-see 对 B4-mm（再感知，H5） | +26 / −2，p < 0.001 | +19 / −5，p = 0.007 |
| B4-mm 对 B4-text（描述 + 事实 + 以文搜图） | +36 / −9，p < 0.001 | +35 / −8，p < 0.001 |
| B4-see 对 B1 | +26 / −5，p < 0.001 | +27 / −8，p = 0.002 |

## 怎么读

- **再感知（H5）成立**：把相关度最高的 3 张原图附给回答模型，两档都显著提升，主要在信息抽取题（32K 41% → 72%，128K 44% → 69%）：颜色、数量、图中文字这类细节，描述写不全，看原图才答得出。代价是每题约 670 个输入 tokens（每张图约 220 tokens），名义成本 +$0.0002。"不知道"式的误拒答从 49 次降到 20 次（32K）。
- **长上下文模型随长度退化，记忆系统靠 L2 保持稳定**：从 32K 到 128K，B1 显著下降（−6 个点）且成本涨 5 倍；L1 的 B4-see 也显著下降（−7 个点，128K 时证据会话的召回从 93% 降到 80%）；L2 的 B5-see 不变（65.6% → 64.6%）——子查询与补检索把证据找回来了（128K 时会话召回 89%）。
- **B5-see 比只给证据会话的 ORACLE 还高**（32K +10 个点）：ORACLE 一次给出全部证据会话与其中所有图片，回答模型要在长对话和十几张图里自己找；B5-see 给的是事实、带描述的片段和挑过的 3 张原图，外加先记笔记再回答。
- **以文搜图提高了检索、没有提高准确率**：关键图片所在轮的召回 32K 62% → 87%、128K 54% → 72%，但端到端在开发集与两档测试集上都没有差异（方向不一）。默认值按开发集的纯检索结果定下（D-036），端到端的结果如实记录；它的价值可能在"挑哪几张原图"而不是"装哪几轮"，留给 N7 / N9。
- **描述的价值**：纯文本记忆只有 37%，加上描述、事实与以文搜图到 51%，误拒答从 88 次降到 49 次。纯文本记忆里大量"不知道"，是因为看不到图。

## 开发集（100 题，32K）

| 方法 | 准确率 | 每题名义成本 | 关键图片所在轮的召回 |
|---|---|---|---|
| B0 无记忆 | 14% | $0.0002 | — |
| B1 全上下文 | 59% | $0.0081 | — |
| B4-text 纯文本记忆 | 38% | $0.0013 | 51.2% |
| B4-cap 对话 + 上下文感知描述 | 48% | $0.0014 | 65.1% |
| B4-iso 对话 + 孤立描述 | 51% | $0.0014 | 60.7% |
| B4-mm 描述 + 以文搜图 + 事实 | 51% | $0.0018 | 86.2% |
| B4-novis B4-mm 去掉以文搜图 | 52% | $0.0016 | 57.0% |
| B4-see B4-mm + 再感知 | 58% | $0.0020 | 86.2% |
| B4-see-novis B4-see 去掉以文搜图 | 61% | $0.0018 | — |
| B5-see L2 + 再感知 | 67% | $0.0044 | 97.7% |
| ORACLE | 59% | $0.0022 | — |

- 再感知：B4-see 对 B4-mm +8 / −1（p = 0.039），信息抽取 +8 / −0。
- 描述：B4-cap 对 B4-text +13 / −3（p = 0.021）。
- **上下文感知描述 vs 孤立描述（H6）没有得到支持**：检索上上下文感知描述略好（关键图片所在轮的召回 65.1% 对 60.7%），端到端反而是孤立描述多对 3 题（+7 / −4，p = 0.55）。例子里能看到原因：上下文感知描述会写出图片在对话里的含义（"用户提到的、上一段感情留下的礼盒"），孤立描述把同样的字数都用在画面细节上；MemLens 的题大多问画面细节。
- B5-see 对 B4-see +13 / −4（p = 0.049）。

## 复现

```bash
uv run cuemem data download memlens_32k memlens_128k
uv run cuemem eval run --dataset memlens_32k --split dev100 --name memlens32-dev100-build --methods B4 --build-only
uv run python scripts/tune_mm.py --dataset memlens_32k --split dev100      # 纯检索，只用通义
uv run cuemem eval run --dataset memlens_32k --split dev100 --name memlens32-dev100-n6 \
  --methods B0,B1,B4-text,B4-cap,B4-iso,B4-mm,B4-novis,B4-see,B4-see-novis,B5-see,ORACLE
uv run cuemem eval run --dataset memlens_32k --split agent195 --name memlens32-agent195-n6 \
  --methods B0,B1,B4-text,B4-mm,B4-see,B4-see-novis,B5-see,ORACLE
uv run cuemem eval run --dataset memlens_128k --split agent195 --name memlens128-agent195-n6 \
  --methods B0,B1,B4-text,B4-mm,B4-see,B4-see-novis,B5-see,ORACLE
```

构建（`--build-only`）只用通义的模型，可以在 DeepSeek 高峰时段跑；遇到通义内容审核误拒时兜底用 deepseek-flash，在高峰时段会暂停到 18:00。
