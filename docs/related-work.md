# 相关工作与定位

> 两个用途：理清本项目借鉴了什么、和谁不同；回答"你的方法和 XX 有什么区别"。
>
> 这里按论文看；GitHub 上工程化的同类项目（Mem0、Letta、Graphiti / Zep、Cognee、Supermemory……）逐项对比、各家公开的分数，以及 N12 照着它们补了什么，见 [landscape.md](landscape.md)。
>
> arXiv 链接均已于 2026-10-12 核对标题。他人报告的数字通常基于不同的 reader、judge 与 prompt，不能直接与本项目比较。

## 1. 对比总览

| 工作 | 谁决定检索 | 记忆结构 | 知识更新 | 多模态 |
|---|---|---|---|---|
| MemGPT / Letta | LLM 自主（函数调用） | 主上下文 + 回忆存储 + 归档存储 | LLM 自行编辑 | — |
| Mem0 | 每次都检索 | 事实（另有图变体） | ADD / UPDATE / DELETE / NOOP | — |
| Zep / Graphiti | 每次都检索 | 时序知识图谱 | 双时间轴、边失效 | — |
| HippoRAG 2 | 每次都检索 | 知识图 + 段落节点 | — | — |
| Adaptive-RAG | 小分类器（按问题复杂度） | —（开放域问答） | — | — |
| Agent Zero Memory | intent gate + source router | 时间线 + 实体-事件图 + 层级文档 | 溯源与证据指针 | — |
| M3-Agent | 模型自主（RL 训练的多轮推理） | 以实体为中心的多模态记忆图 | — | 视频 + 音频 |
| **CueMem（本项目）** | **可学习的控制器 + 记忆探针，λ 调节成本** | **事实 + 实体图 + 多粒度索引** | **双时间轴，失效而不删除** | **图片 + 再感知（视频 ☆）** |

"—"表示不是该工作的重点（依据论文摘要与公开介绍）。

## 2. Agent 记忆系统

| 工作 | 核心思想 | 本项目借鉴 / 区别 |
|---|---|---|
| [MemGPT](https://arxiv.org/abs/2310.08560)（2023，后发展为 Letta） | 借鉴操作系统的虚拟内存：有限的主上下文 + 外部存储，LLM 通过函数调用自主换入换出、编辑记忆 | 借鉴"核心记忆常驻"；区别：检索时机不交给 LLM |
| [Generative Agents](https://arxiv.org/abs/2304.03442)（UIST 2023） | 记忆流；检索分 = 新近性 + 重要度 + 相关性；通过反思生成高层记忆 | 借鉴打分特征与"巩固出高层记忆" |
| [MemoryBank](https://arxiv.org/abs/2305.10250)（AAAI 2024） | 按艾宾浩斯遗忘曲线更新记忆强度 | 借鉴强度衰减与访问强化，但只用于排序、不删除 |
| [Mem0](https://arxiv.org/abs/2504.19413)（2025） | LLM 抽取候选记忆，与相似的旧记忆比较后执行 ADD / UPDATE / DELETE / NOOP；图变体存实体关系；报告相对全上下文大幅降低延迟与 token | 借鉴对账操作；区别：失效而不删除（保留历史）；合并、否定由规则判定，取代才调用 LLM（批量），并区分"现实变了"与"认知变了"两种取代（N3，D-019）；读取侧有可学习的控制器 |
| [Zep](https://arxiv.org/abs/2501.13956)（2025，Graphiti 引擎） | 时序知识图谱：情景、语义实体、社区三层子图；双时间轴；出现矛盾时让旧边失效；混合检索 | 借鉴双时间轴；区别：嵌入式轻量实现；记录时间取对话时间，迟到的旧消息不覆盖新状态；遗忘按"删日志 + 重放"实现（N3，D-020、D-021）；控制器；多模态 |
| [A-MEM](https://arxiv.org/abs/2502.12110)（2025） | Zettelkasten 式笔记：自动建立记忆之间的链接，新记忆会触发旧记忆属性的"演化" | 参考记忆之间的链接 |
| [Memory OS of AI Agent](https://arxiv.org/abs/2506.06326)（2025，MemoryOS） | 短期、中期、长期个人记忆的分层存储与更新 | 参考分层 |
| [MIRIX](https://arxiv.org/abs/2507.07957)（2025） | 六类记忆，由多个智能体分别管理，覆盖屏幕截图等多模态输入 | 参考记忆类型划分 |
| [MemOS](https://arxiv.org/abs/2507.03724)（2025） | 统一管理明文记忆、激活记忆（KV cache）、参数记忆的"记忆操作系统" | 开阔视野：外部记忆之外的形态 |
| [Memory-R1](https://arxiv.org/abs/2508.19828)（2025） | 用强化学习训练记忆管理器（ADD / UPDATE / DELETE / NOOP）与回答智能体 | 与控制器的 RL / bandit 扩展方向相关 |
| [MemAgent](https://arxiv.org/abs/2507.02259)（ICLR 2026，字节 Seed 与清华 AIR） | RL 训练的智能体分段阅读长文本、覆写固定长度的记忆，以线性复杂度处理超长上下文（8K 窗口外推到 3.5M token 问答） | 另一条路线：把"记什么"学进模型的工作流；与外部记忆互补 |
| [Agent Zero Memory](https://arxiv.org/abs/2608.29606)（2026） | 溯源感知：每条记忆带来源、时间与证据指针，回答只能引用实际读过的证据，否则拒答；情景时间线 + 实体-事件图 + 层级文档记忆；读路径有 intent gate 与 source router；报告 LongMemEval 95.60%、LoCoMo 93.60%，8 种底座间准确率只差 3.4 个百分点 | **最接近的工作**，验证了 memory-driven 路线；区别见 §9 |

## 3. 结构化与图检索

| 工作 | 核心思想 | 本项目借鉴 |
|---|---|---|
| [HippoRAG](https://arxiv.org/abs/2405.14831)（NeurIPS 2024） | 受海马体索引理论启发：用 OpenIE 构建知识图，从查询实体出发运行个性化 PageRank，一步完成多跳检索 | L2 的图扩散直接借鉴 |
| [HippoRAG 2](https://arxiv.org/abs/2502.14802)（2025） | 在 HippoRAG 基础上加入段落节点、查询与三元组的匹配等，兼顾事实记忆、意义理解与联想 | 借鉴"实体 + 段落"混合图 |
| [GraphRAG](https://arxiv.org/abs/2404.16130)（2024） | 社区检测 + 社区摘要，回答全局性、总结性问题 | 参考多层摘要 |
| [LightRAG](https://arxiv.org/abs/2410.05779)（2024） | 图与向量结合的双层检索，支持增量更新 | 参考增量更新 |
| [RAPTOR](https://arxiv.org/abs/2401.18059)（ICLR 2024） | 递归聚类与摘要构建多层树，跨层检索 | 参考多粒度索引 |

## 4. 自适应检索：何时检索、检索多深

| 工作 | 核心思想 | 与本项目的关系 |
|---|---|---|
| [Self-RAG](https://arxiv.org/abs/2310.11511)（ICLR 2024） | 训练 LM 输出反思 token，自己决定是否检索并评判生成 | 需要训练生成模型；本项目把决策放在模型之外 |
| [FLARE](https://arxiv.org/abs/2305.06983)（EMNLP 2023） | 生成中出现低置信度 token 时，以预测的下一句为查询触发检索 | 基于模型不确定度；在私人记忆场景可靠性存疑（H1） |
| [DRAGIN](https://arxiv.org/abs/2403.10081)（ACL 2024） | 结合 token 不确定度、注意力等信号判断实时信息需求 | 需要模型内部信号，API 模型通常拿不到 |
| [Adaptive-RAG](https://arxiv.org/abs/2403.14403)（NAACL 2024） | 小分类器按问题复杂度选择不检索 / 单步 / 多步；标签由"哪种策略答对"自动构造 | **控制器的方法论来源**；区别：用于私人长期记忆、加入记忆侧探针特征、效用决策 + 成本旋钮、反应式升级 |
| [CRAG](https://arxiv.org/abs/2401.15884)（2024） | 轻量评估器判断检索质量，据此触发纠正动作 | 借鉴"充分性检查后升级" |
| [FrugalGPT](https://arxiv.org/abs/2305.05176)（2023） | LLM 级联：先用便宜模型，不满意再升级 | 借鉴级联思想（L0 → L1 → L2） |

## 5. 长上下文的局限

| 工作 | 结论 |
|---|---|
| [Lost in the Middle](https://arxiv.org/abs/2307.03172)（TACL 2024） | 相关信息位于长上下文中间时，模型利用效果明显变差 |
| [RULER](https://arxiv.org/abs/2404.06654)（2024） | 多数模型的有效上下文长度远小于宣称值 |
| [NoLiMa](https://arxiv.org/abs/2502.05167)（2025） | 去掉问题与答案之间的字面重合后，长上下文表现随长度急剧下降 |
| [Context Rot](https://research.trychroma.com/context-rot)（Chroma，2025） | 即使任务简单，输入变长也会让表现下降 |

这些工作支撑"长上下文 ≠ 记忆"的论证，也是 B1 全上下文基线的预期依据。

## 6. 多模态记忆与检索

| 工作 | 核心思想 | 与本项目的关系 |
|---|---|---|
| [M3-Agent](https://arxiv.org/abs/2508.09736)（2025，字节 Seed） | 处理实时视觉与听觉输入，构建以实体为中心的多模态长期记忆（情景 + 语义）；RL 训练的多轮推理检索；提出长视频问答基准 M3-Bench | 视频方向的参照（本项目的扩展项）；区别：聚焦对话中的图片记忆与成本感知检索 |
| [MemLens](https://arxiv.org/abs/2605.14906)（2026） | 图文多会话记忆基准；发现长上下文 LVLM 随长度退化，记忆智能体因存储时压缩丢失视觉细节 | 主多模态基准；其发现直接驱动"再感知"设计 |
| [Mem-Gallery](https://arxiv.org/abs/2601.03515)（ACL 2026） | 图文多会话记忆基准，从记忆抽取与测试时适应、记忆推理、记忆知识管理三个维度评测 | 可选补充基准 |
| [ColPali](https://arxiv.org/abs/2407.01449)（2024） | 用 VLM 直接对文档页面图像做 late-interaction 检索 | 截图、文档类图片的进阶方案 |
| [SigLIP 2](https://arxiv.org/abs/2502.14786)（2025） | 多语言图文编码器 | 图像向量候选 |
| [Qwen3-VL-Embedding](https://arxiv.org/abs/2601.04720)（2026） | 把文本、图片、文档图像、视频映射到统一向量空间；2B / 8B 两档 | 中国大陆的千问 AI 平台提供 API 版本；本项目使用的 QwenCloud 暂时没有，N6 先用 tongyi-embedding-vision-plus |
| [BGE-M3](https://arxiv.org/abs/2402.03216)（2024） | 一个模型同时输出 dense、sparse、multi-vector 表示，多语言 | 文本向量候选 |

## 7. 评测基准

| 基准 | 内容 | 用途 |
|---|---|---|
| [LongMemEval](https://arxiv.org/abs/2410.10813)（ICLR 2025） | 500 题，五种能力：信息抽取、多会话推理、时间推理、知识更新、拒答；S 版每题历史约 115k tokens；论文还提出会话分解、事实增强键、时间感知查询扩展等优化 | 主文本基准；多项设计直接借鉴 |
| [LoCoMo](https://arxiv.org/abs/2402.17753)（ACL 2024） | 超长多会话对话（平均约 300 轮、9K tokens、最多 35 个会话），对话中含图片分享；任务包括问答、事件摘要、多模态对话生成 | 次文本基准 |
| [BEAM](https://arxiv.org/abs/2510.27246)（2025） | 百万到千万 token 量级的长期记忆基准 | 可选的规模压力测试 |
| MemLens、Mem-Gallery | 见 §6 | 多模态基准 |

## 8. 理论框架

| 工作 | 核心思想 | 与本项目的关系 |
|---|---|---|
| [CoALA](https://arxiv.org/abs/2309.02427)（TMLR 2024） | 语言智能体的认知架构：工作记忆、情景记忆、语义记忆、程序性记忆 | 记忆类型划分的依据 |
| [Sleep-time Compute](https://arxiv.org/abs/2504.13171)（2025） | 在空闲时间预先计算，降低在线推理开销 | 异步巩固的依据 |
| 编码特异性原则（Tulving & Thomson, 1973） | 检索线索与编码时的情境越匹配，回忆越成功 | "线索驱动"命名的由来：写入时保存情境（时间、实体、对话），读取时抽取线索去匹配 |

## 9. 本项目的定位

1. **相对模型驱动的记忆管理**（MemGPT、Agentic RAG、M3-Agent 的推理检索）：把"何时检索、检索多深"从模型中解耦，做成可训练、可单独评测的控制器；模型自主检索保留为对照基线和逃生通道。
2. **相对工程化记忆系统**（Mem0、Zep、Agent Zero Memory）：它们证明了 memory-driven 路线有效。本项目把 gate 本身作为研究对象：标签怎么构造、成本旋钮怎么调、帕累托前沿在哪里、与模型自主检索正面比较的结果如何；并补上多模态再感知。
3. **相对自适应检索方法**（Adaptive-RAG、Self-RAG、FLARE、DRAGIN）：从开放域知识问答迁移到私人长期记忆，用记忆侧探针特征替代或补充模型不确定度，也适用于拿不到模型内部信号的 API 模型。
4. **相对多模态记忆基准的发现**（MemLens）：针对"存储时压缩丢细节"与"长上下文随长度退化"的两难，给出"压缩索引 + 按需再感知"的折中，并由控制器管理图片 token 成本。

## 10. 建议精读顺序

1. LongMemEval：理解问题与评测维度；
2. Mem0 → Zep：两种工程化记忆的写入与更新方式；
3. Adaptive-RAG：控制器的方法论来源；
4. HippoRAG 2：图扩散检索；
5. Agent Zero Memory：2026 年与本项目最接近的系统；
6. MemLens：多模态记忆的问题定义；
7. M3-Agent、MemAgent：字节 Seed 的两条记忆路线。
