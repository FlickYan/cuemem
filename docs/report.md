# CueMem 技术报告

> v1.2 · 2026-10-15 · N12 · [English](en/report.md)。本文汇总整个项目的设计与最终评测（N9）、测试集用过之后的补做（N11，§12），以及 N12 的同协议外部对比（§13）；各节点的细节与开发集上的实验见 [docs/results/](results/)，设计取舍见 [decisions.md](decisions.md)。
>
> **LongMemEval 数字的披露（N12）**：N2–N11 报告的 LongMemEval 数字里，凡是检索类方法，回答模型都能从检索结果抬头里的会话 ID 认出哪些片段来自证据会话（证据会话的 ID 都以 `answer_` 开头）。N12 发现并修复了这个泄漏（D-067）。消融（B2、L1、L2、控制器与 Mem0）没有测出它对 CueMem 数字的影响；模型自主检索（B3、B6a）没有做消融。Mem0 发布的数字可能高了几个点。本文的数字照原样保留，详见 §3.5 与 [N12 泄漏记录](results/n12-leak/README.md)。

## 摘要

CueMem 是一个给 LLM Agent 用的长期记忆系统，由四部分组成：

- **写入**：原始日志不可变，异步巩固出带有效期的事实。
- **检索**：三档（L0 只给画像、L1 快速召回、L2 深度检索）。
- **控制器**：一个不调用 LLM 的检索控制器，决定每一问"要不要想起、想多深"。
- **多模态**：回答时把原图取回来再看一遍。

最终评测在三个测试集上进行：LongMemEval test400、LoCoMo 后 7 段对话（1,155 题）、MemLens 195 题。方法与配置事先冻结，测试集只用一次。

- **记忆系统比全上下文又准又便宜**：LongMemEval 上 L1 90.5% 对 73.0%，成本约 1/20；MemLens 128K 上 L2 + 再感知 65.1% 对 46.2%。
- **写入路径是最大的单项收益**：朴素检索加上写入路径的产出，LongMemEval 82.0% → 91.0%。
- **冻结的控制器在测试集上复现了开发集的估计**（记忆题 81.2% → 81.6%）。在 20% 记忆题的混合流里，它比"总是检索"便宜 41%、准确率不降；但在纯记忆题上始终低于总是 L2（合并低 2.8 个点）。它的价值在"要不要想起"，不在"想多深"。
- **让模型自主检索（ReAct）各有所长**：文字记忆上最强（LoCoMo 85.5%），图片记忆上失灵（MemLens 46.7%）。"控制器先选、模型兜底"在三个数据集上都稳，但最贵。
- **真正"检索没取到"的错题很少**：多的是控制器选错档、计数漏数，以及 LoCoMo 标准答案本身的问题（抽查的 40 道错题里有 10 道）。
- **N2–N11 的数字都能从本地缓存一键重放**，控制器的真实运行与离线重放逐题一致。
- **同协议的外部对比（N12，LoCoMo 200 题，§13）**：只用 DeepSeek 的协议下，L2 87.0% 高于 Mem0（81.0%）、LangMem（78.0%）、Cognee（77.5%）、Graphiti（59.0%）与 A-MEM（58.0%），多重比较校正后对后四个仍显著，对 Mem0 只是名义显著（p = 0.017，校正后 0.068）；L1（82.5%）与 Mem0、LangMem、Cognee 的差别不显著。A-MEM 用作者给 GPT-4o 级模型的 k = 40 时升到 75.0%，L1、L2 仍显著更高。Graphiti 与 LangMem 对抽取模型很敏感：换成只用通义，Graphiti 降到 41.5%，LangMem 降到 30.0%。

## 1. 问题

LLM Agent 要在跨越数月、上百个会话的交互里**记得住、想得起、记得准**：用户说过的偏好、计划、换了的工作与预算、分享过的照片，都要在之后某一天被问到时答得出来，而且答的是最新的那个版本。

把全部历史塞进上下文不是答案：成本随历史线性增长，模型对长输入里的信息用得越来越差（LongMemEval、Lost in the Middle），而且新旧说法并存时要靠模型临场判断。本项目把记忆当作信息管理问题来做，并回答一个具体问题：**"这一轮要不要想起、想多深"应该由谁决定**——让 LLM 自己调用检索工具，还是由一个便宜、可训练、可度量的控制器决定。

## 2. 系统

```text
用户消息 ──► 记忆探针（不调用 LLM，p50 0.2–0.5 秒）──► 检索控制器 ──► L0 只给画像
                                                        ├──► L1 快速召回（不调用 LLM）
                                                        └──► L2 深度检索（规划、补检索、记笔记）
                                                              （有图时再决定要不要附原图）
         ──► 在线写入（原始日志、向量、原图）──► 后台巩固（事实、实体、有效期、画像、图片描述）
```

### 2.1 写入：原始日志 + 异步巩固（N3）

- **原始日志不可变**，是唯一的事实来源。在线写入只追加发言、建向量索引、存原图（按内容哈希），不调用 LLM。
- **巩固**在后台按会话进行：抽取原子事实与实体（qwen3.8-flash）、实体消歧、事实对账、会话摘要、图片描述、核心记忆（画像）。派生记忆全部可以从日志重放。
- **双时间轴有效期**：事实带事件时间（valid_from / valid_to）与记录时间（recorded_at / invalidated_at）。"我搬到新加坡了"（现实变了）与"我说错了，其实是上海"（认知变了）都让旧事实失效，但含义不同；旧事实保留，问"以前"时还答得出来。
- **对账**：规则只管合并、否定与多值累积，"取代"一律由 LLM 确认。首轮按规则取代的精确率只有约 10%，错误的"已失效"标签比没有更糟（D-019）。
- **遗忘**：从日志删除 + 用剩下的日志重放派生记忆 + 按归属清理缓存（D-021）；N8 起以整轮为单位、沿引用扩散（D-046）；N10 起还会在原始日志里找没有引用、只是转述了它的发言（D-051；N11 之后改为只删那条发言、不从它出发沿引用扩散）。

### 2.2 读取：三档检索（N4、N5、N7）

| 档 | 做法 | 额外的 LLM 调用 |
|---|---|---|
| L0 | 只给常驻上下文（核心记忆 / 画像） | 无 |
| L1 | 轮、事实、摘要、图片描述多路 dense 召回，模态内取最大、模态间 RRF；时间表达加分；按 token 预算（4k）打包，每条证据标"距提问几天" | 无（一次查询向量化） |
| L2 | 查询规划（子查询、时间区间）→ 多查询"取最好名次"融合 → 充分性检查与补检索 → 先记笔记再回答 | 2–4 次便宜模型调用 |

L1 的设计由纯检索指标调出：按 token 预算打包是最大的单项杠杆（LoCoMo 一轮只有一句话，固定取 10 轮会少掉四分之三的上下文，D-029）；换向量模型（text-embedding-v4 → qwen3.7-text-embedding）的收益超过所有检索技巧（D-014）。L2 里最大的杠杆是"先记笔记再回答"，图扩散与重排实现了但实测无益，默认关闭（D-030 至 D-032）。

### 2.3 检索控制器（N7）

- **记忆探针**：一次 L1 打分（选了 L1 时候选直接复用），产出 54 个特征：问题线索（第一人称、指向过去的对话、时间与聚合表达、视觉词……）、检索分数分布、命中的分散程度与时间跨度、被取代的事实、实体与图片命中、记忆规模。
- **两段式控制器**：门控估计"这一问与记忆无关"的概率，推理类型模型（七类）估计是哪类记忆题；查"这类题在各档上的准确率"，按 P̂(答对) − λ · 成本选动作（L0 / L1 / L2，有图时 ± 再感知）。标签用推理类型作中介，而不是逐题的"答没答对"——后者被回答的随机翻转污染（D-038）。
- **λ 是业务旋钮**："多答对一题愿意多付多少钱"；默认 λ = 30 按"不比总是检索差的前提下最省钱"事先选定（D-040）。参数导出成 JSON，运行时两次矩阵乘法。

### 2.4 多模态（N6）

图片的三种表示：原图（按内容哈希存放）、图文同空间的视觉向量（以文搜图、以图搜图）、两种描述（结合对话上下文的、只看图的）。描述填回原话参与事实抽取，也作检索键。**回答时再感知**：附上最相关的 3 张原图——存储时压缩换长度稳定，回答时取回原图换视觉保真（D-003、D-037）。

### 2.5 Agent Runtime（N8）

自研的对话循环：控制器先选档召回，模型可以用 `memory_search` 自己补查（D-042）；上下文按分区预算装配，系统提示、画像快照、本次对话的原话组成稳定前缀，召回的记忆只放在最后一条消息里（D-043）；每轮在线写回，会话结束后台巩固（D-045）。另有 FastAPI 接口、可解释的 Gradio 界面（记忆轨迹面板、记忆浏览器）与 MCP Server。

## 3. 评测设置

### 3.1 数据与划分

| MemLens（图文交错，80% 的题需要图片证据） | 官方 195 题记忆智能体子集，32K 与 128K 两档 | 子集外分层抽的 100 题（32K） |

| L0 | 只给核心记忆（画像） |

### 3.3 回答模型与判分

- 主回答模型 deepseek-flash（关闭思考模式，能读图）；判分 qwen3.8-max，与主回答模型不同家族（D-008）。判分提示词逐字照搬 LongMemEval 官方模板（LoCoMo 沿用同一模板，D-015）与 MemLens 官方提示词（D-034）。
- 换回答模型（H3）：小模型 qwen3.6-35b-a3b（混合专家，每次激活约 3B 参数）、qwen3.8-flash、大模型 deepseek-v4-pro（因账户余额未跑，见 §6），在 `test100r`（test400 分层抽 100 题）与 `test200r`（LoCoMo 测试集分层抽 200 题）上评测。qwen3.8-flash 与判分模型同一家族，它和其他回答模型之间的绝对准确率不能直接比，同一回答模型下方法之间的比较仍然有效。

### 3.4 成本与统计

- 成本统一按名义标价（高峰时段、未命中缓存）计算，便于不同时间跑的实验比较；实际花费（扣除本地缓存命中、供应商缓存折扣、DeepSeek 错峰半价）单独统计（D-010）。DeepSeek 的调用全部放在非高峰时段（D-024）。
- 置信区间用 bootstrap（95%）；同一批题上两种方法的比较用配对符号检验（只看"一个对、一个错"的题）。
- 多重比较（第二轮体检之后补记，D-069）：文中的 p 都是单个比较的。一份结果里做了很多个检验时，`scripts/multiplicity.py` 按族做 Holm 校正（例如 N9 每个数据集的总体对比、同一对比的分题型、控制器、同一回答模型下的对比各是一族；N12 每个协议里"L1、L2 对外部系统"是一族），写在各结果旁边的 `*-holm.json` 里。校正后不再显著的结论在文中标成"名义显著"，并写上校正后的 p；准确率、胜负与原始 p 都没有改。没有存成 JSON 的结论（N5、N6 与 N9 合并三个数据集的控制器对比）按文中的胜负重算，见 D-069。
- 本地响应缓存让每个结果都能免费重放：控制器类方法选中的那一档与固定档位的请求逐字相同，直接命中缓存——所以"B6 的真实运行"与"冻结模型的离线重放"可以逐题核对。

### 3.5 LongMemEval 的会话 ID 泄漏（N12 补记）

N12 查出：N2–N11 的 LongMemEval 评测里，回答模型能认出哪些检索结果来自证据会话（D-067）。

- **怎么泄漏的**：LongMemEval_S 的 948 个证据会话，ID 都以 `answer_` 开头（30 道拒答题的证据 ID 还带 `_abs`）；其他会话以 `sharegpt_`、`ultrachat_` 开头或是十六进制串。回答提示里每条检索结果的抬头都印着"· session <ID>"。
- **受影响的**：所有检索类方法，包括 B2、B3 / B6a 的工具输出、L1、L2、控制器与 Mem0。N2–N11 发布的检索类方法的 LongMemEval 数字都有这个泄漏。
- **不受影响的**：B0、L0、B1（全上下文按 1..n 给会话编号）、ORACLE；LoCoMo（会话 ID 是按时间的序号 session_1..N）；MemLens（原始 ID 是 `sess_<哈希>`，不透露证据）。
- **修复**：载入时把 LongMemEval / MemLens 的会话在每道题的历史里按日期改写成 `session_<i>`，原始 ID 只留在内部、不给模型看；两种写法的写入分开存，不混用。LoCoMo 的请求逐字不变。审查还查出 Cognee（N12 接入的外部基线，§13）的会话蒸馏把 LongMemEval 的题号（含 `_abs`）带进了它的经验文档，一并修好（没有用在已发布的数字里）。

**影响有多大。** LongMemEval test100r 上跑三臂，回答与判分相同：

- raw：原始 ID，即修复之前的条件；
- anon：修复后的默认；
- label：修复后的记忆空间，回答模型看到的检索结果抬头里换回原始会话 ID。

label 对 anon 只差抬头里的会话名，是泄漏本身的效应。raw 对 label 是改名带来的噪声：同一会话内各轮的先后按含会话 ID 的哈希排，改名会重排它们（按哈希排序早就如此，LoCoMo 上也是；LoCoMo 不改名，顺序不变）。原协议（与 N9、N11 相同的配置）：

| 方法 | 修复前（raw） | 修复后（anon） | 抬头换回原始 ID（label） | label 对 anon | N11 发布（另一次运行） |
|---|---|---|---|---|---|
| B1 全上下文 | 81.0% | 81.0% | — | 不受影响 | 80.0% |
| B2 朴素检索 | 82.0% | 86.0% | 87.0% | +4 / −3 | 86.0% |
| CueMem L1 | 92.0% | 90.0% | 92.0% | +3 / −1 | 92.0% |
| CueMem L2 | 93.0% | 96.0% | 95.0% | +2 / −3 | 96.0% |
| CueMem 控制器 | 88.0% | 89.0% | 90.0% | +3 / −2 | 92.0% |
| Mem0 | —（原协议没跑） | 79.0% | 85.0% | +9 / −3（p = 0.15） | 83.0% |

raw 一臂与 N11 发布的数字是同一配置、同样用原始 ID，却不逐题相同，有的差 3–4 个点（朴素检索 82.0% 对 86.0%、控制器 88.0% 对 92.0%）。N11 的 CueMem 数字取自 N9 的运行；raw 一臂在另一个目录里重新写入（几乎都命中缓存）、重新回答，回答本身也有波动（§12.3）。差在哪里没有单独查清，所以看泄漏只比同一批运行的三臂。

- **L1、L2 与控制器没有可测的虚高。** 单个方法的 label 对 anon 都不显著。把检索类方法合在一起（同一批题，彼此不独立）：原协议 +21 / −12（+1.8 个点，p = 0.16，含 Mem0）；只用通义的协议（pq，§13.1；回答模型 qwen3.8-flash）+10 / −14（−1.0 个点，p = 0.54）。全上下文不受影响，检索方法与全上下文之间的差距没有可测的变化。
- **改名的噪声与泄漏同一量级。** B2、L1、L2、控制器合计：只改名（raw 对 label）+5 / −14（−2.25 个点，p = 0.064）；修复前对修复后（raw 对 anon）+8 / −14（−1.5 个点，p = 0.29），修复前反而略低。
- **Mem0 的变化最大**（+9 / −3，p = 0.15）。N11 发布的 Mem0 83.0% 可能高了几个点；修复后同一配置是 L1 90.0%、Mem0 79.0%，L1 对 Mem0 +15 / −4（名义 p = 0.019；这一臂里对 Mem0 的 4 个比较一起校正后 0.058）。
- **局限**：每臂只跑一次；改名本身会重排会话内各轮，带来噪声；学到的控制器的准确率表与 λ 是在泄漏下的结果上拟合的，修复后没有重新拟合；模型自主检索（B3、B6a）、B2F、L1 + 先记笔记与 §6 里小模型那一档没有做这个消融。
- **已发布的数字不改。** N2–N11 的 LongMemEval 数字照原样保留。`scripts/reproduce.py` 对这些步骤沿用原始 ID（`CUEMEM_EVAL_RAW_SESSION_IDS=1`），提示与当时逐字相同，有当时的响应缓存时照样重现；之后的 LongMemEval 运行默认用改写后的 ID。

细节与原始数字见 [N12 泄漏记录](results/n12-leak/README.md)。

- **混合流里，B6 比"总是检索"便宜 41%，记忆题准确率还高 1.3 个点**（开发集估计 45%）。区分记忆题与无关查询的 AUC 是 0.990（开发集 0.983）；探针 p50 163–487 ms，取决于记忆空间的大小。
- **纯记忆题上，它夹在两个固定档位之间**：对总是 L1 +60 / −37（p = 0.025，未校正：合并三个数据集的逐题结果没有存进 JSON；只与对总是 L2 的比较放在一族时仍是 0.025），对总是 L2 +15 / −64（p < 0.001）。H2 的结论与 N7 相同：混合流那一半成立，纯记忆题那一半不成立。

### 5.3 MemLens 上的一个设计缺陷：看图增益饱和

控制器在有图的空间里估计"L1 + 看图""L2 + 看图"的成功率时，把这类题的看图增益加到不看图的成功率上，再截断到 1.0（`action_proba`）。开发集上看图的增益很大，加完之后两档常常都被截成 1.0，排序信息丢了，代价项就总选便宜的 L1。

| MemLens 32K 上 B6 的选择 | 题数 | B6 | 总是 L1 + 看图 | 总是 L2 + 看图 |
|---|---|---|---|---|
| L0 | 11 | 2 | 8 | 7 |
| L1 + 看图，两档都被截成 1.0 | 49 | 36 | 36 | 41 |
| L1 + 看图，没有截断 | 22 | 20 | 20 | 20 |
| L1 不看图 | 4 | 3 | 3 | 4 |
| L2 + 看图 | 109 | 56 | 56 | 56 |

B6 输给总是 L2 + 看图的 13 道题里，6 道在"被截断"那一组，5 道是门控把记忆题放到了 L0（多是指代已分享图片、没有第一人称线索的问题，N7 的零样本 LLM 路由也漏这类）。改法很直接：看图增益改在对数几率上相加，或者在截断前比较。但测试集上发现的问题这次只记录、不回头改（D-048）。

> **N11 补记**：事后重放显示"改法很直接"过于乐观。改用图片空间的准确率表之后，这 6 道确实救回来了，但另外 70 来道题的选择也跟着变了，32K 上净值为零；净收益来自"有图的空间里问画面细节不选 L0"这条保底规则（§12.1）。

## 8. 错误分析

分两层：

- **自动归因**：按规则给全部错题分类（控制器没检索 / 误拒答 / 检索未命中 / 命中而 ORACLE 答对 / ORACLE 也答错）。
- **人工标注**：从 B6（默认部署的做法）的错题里按题型分层抽 40 道逐题看（LongMemEval 只错 38 道，全看），标注成 11 类。定义见 `scripts/n9_errors.py`；标注只存题号与标签，在 [error_labels.json](results/n9-final/error_labels.json)。看图题的错题还核对了回答时附的原图里有没有证据图。

"控制器选错档"的口径有三种情况：

- 记忆题被放到了 L0；
- 选了 L1，换 L2（附图与否不变）就能答对；
- 该附原图却没附。

反过来"选了 L2 答错、L1 能答对"不算，那是 L2 自身的波动。

| 人工标注 | LongMemEval（38 / 38） | LoCoMo（40 / 206） | MemLens 32K（40 / 78） |
|---|---|---|---|
| 控制器选错档 | **16** | 3 | **9** |
| 计数 / 求和 / 列举 | 9 | **10** | 6 |

### 8.1 LongMemEval：最大的一类是选错档

> **N12 补记**：这些错题来自修复会话 ID 泄漏（§3.5）之前的运行。

| 类型 | 题数 | 例子 |
|---|---|---|
| 控制器选错档 | 16 | 门控把 6 道记忆题放到了 L0，换 L1 全部答对。这些问题没有"我上次说过"之类的线索，例如"我们公司的领导岗位里女性占百分之几？""西红柿和万寿菊哪个先播种？"。另 10 道选了 L1、L2 能答对，例如"洒红节和圣玛丽教堂的周日弥撒隔了几天"：L1 拿到了两个日期（2 月 26 日、3 月 19 日）却算成 7 天，L2 答对了（21 天） |
| 计数 / 求和 / 列举 | 9 | "今年参加了几场婚礼"答 5 场，应为 3 场：把姐姐的婚礼和"九月戴项链的那场"也算了进去。"六座博物馆的先后顺序"漏掉了最早的科学博物馆 |
| 标准答案有误或推不出 | 3 | "流感好了之后过了几周跑了第十次步"：1 月 19 日到 4 月 10 日是 11.6 周，标准答案是 15 周 |
| 日期推算 | 3 | "我几周前去了 Summer Nights 节"答 6 周，应为 3 周 |
| 用了过时的版本 | 2 | "我现在把旧球鞋放在哪"答"床底下"，后来的会话说放到了衣柜的鞋架上 |
| 误拒答 | 2 | 七点出门、路上两小时，"几点到的诊所"答"不知道" |
| 判分过严 | 2 | 标准答案"澳大利亚的墨尔本大学"，回答"墨尔本大学" |
| 证据没进上下文 | 1 | |

- **选错档的 16 道里，L1 → L2 的 10 道集中在多会话计数与时间推算。** 这正是 L2 的笔记擅长的；另有 3 道是偏好题。
- **门控漏判的比例与开发集的估计一致。** LongMemEval 上 B6 把 7 道题（1.8%）放到了 L0，6 道答错；三个测试集合并的漏召回是 1.1%，开发集估计是 2.4%。
- **记忆的有效期标错了一次。** 对账把三条范围不同的起床时间串成了一条新旧链："工作日 6 点半" → "每天 7 点半" → "周五 6 点"。问"周五比其他工作日早起多久"时，模型看到"工作日 6 点半"已被标为作废，只好给出两个条件答案。范围不同（工作日 / 每天 / 周五）的事实不该互相取代，这是 D-019 讨论过的那类错误。

## 9. 研究假设的结论

| 编号 | 假设 | 结论 |
|---|---|---|
| H1 | 判断"检索多深"时，探针反馈 + 查询线索特征优于仅用查询文本，也优于基于模型不确定度的触发 | **部分成立**。"要不要记忆"上成立：开发集上只看问题线索的 AUC 0.79、只看探针反馈 0.96、两者合用 0.98；冻结的门控在测试集上 0.990。按模型不确定度逐级升级最差（N7）。"L1 还是 L2"上不成立：推理类型主要看问题怎么问；测试集上 B6 的深度决策比总是 L1 好（+60 / −37），离总是 L2 还差 2.8 个点 |
| H2 | 控制器能在与 always-L2 相近的准确率下显著降低平均成本 | **纯记忆题上不成立，混合流里成立。** 测试集上 B6 比总是 L2 低 2.8 个点（+15 / −64）、便宜 31%；20% 记忆题的混合流里比"总是检索"便宜 41%，记忆题准确率不降（+1.3 个点）。与开发集的估计一致 |
| H3 | 相比模型自主检索，控制器在不同回答模型之间更稳定，在小模型上优势更大 | **不成立**（三个回答模型；大模型一档因余额未跑）。B3 跨模型的波动不比 B6 大；最小的模型上 B3 只在 LoCoMo 上略吃亏（对 L2 +9 / −20，p = 0.061）。控制器自己的问题是"各档准确率"按主回答模型标定，换小模型后照样大量选 L1（N11：重新标定无效，按回答模型调 λ 有效，§12.1）。"控制器先选、模型兜底"在各回答模型下都不是最差的 |
| H4 | 有效期机制（失效而不删除）提升知识更新类问题，且不损害历史状态类问题 | **未得到支持。** 测试集的知识更新题上，完整版、"只给当前事实"、"不标有效期"三种写法都是 96.5%：原始对话仍在上下文里，模型自己就能分辨新旧。完整版对两个消融的优势（+15 / −6、+13 / −7）来自多会话题，不显著。写入路径整体的收益很大（+9 个点），但不来自有效期标签 |
| H5 | 回答时再感知原图显著提升需要视觉细节的问题，图片 token 成本可由控制器控制 | **成立**（N6；N9 用的是同一个测试集）。L1 附 3 张原图：32K +12.3 个点（+26 / −2）、128K +6.7 个点（+18 / −5），集中在信息抽取题。控制器的确在控制附不附图，但看图增益的截断让它在 L1 + 看图与 L2 + 看图之间选错（§5.3；N11 的修正见 §12.1） |
| H6 | 上下文感知的图片描述优于孤立描述，在实体绑定类问题上尤其明显 | **未得到支持**（N6，N9 没有再测）。检索上略好，端到端孤立描述反而多对 3 题（n.s.）；MemLens 多问画面细节（D-035） |

六个假设里，完全成立的只有 H5，H1、H2 各成立一半。被否证的那几条同样说明了问题：

- **"想多深"能挣的很少**（H1 后半、H2）；
- **会用工具的模型自己决定检索也很好**（H3）；
- **有效期标签在答题准确率上没有可测的收益**（H4）。它的价值在于能说清"什么时候、为什么变了"，例如 N8 演示里预算从 $120 改到 $180。

## 10. 局限与教训

### 10.1 局限

- **判分只用一个模型。** qwen3.8-max 与主回答模型不同家族（D-008），判分模板逐字照搬官方；但人工复核的错题里有 2 / 38（LongMemEval）、4 / 40（LoCoMo）、5 / 40（MemLens）是判分过严，绝对准确率偏保守。同一判分下方法之间的比较不受影响。
- **每个组合只跑一次。** 温度 0 下回答仍会因证据的细微差别而翻转（N7：585 题里 L2 救回 45 题、又弄错 17 题），配对检验能分辨的差异大约在 3–5 个点以上。
- **MemLens 测试集在 N6 已经报告过一次**（那时的方法也是事先定的，D-048）；N9 的 MemLens 数字与 N6 有 ±1–3 题的出入：N6 的 32K、128K 两个运行同时进行，完全相同的请求并发时谁先写进缓存不确定（查到 1 次判分、3 个 L2 查询计划不同）。"可复现"指从缓存重放逐字一致，从零重跑会有这个量级的波动。
- **控制器只在开发集的 585 道题上训练**，跨数据集不能零样本迁移（N7）。测试集上发现三个问题，按 D-048 当时只记录、不回头改：
  - MemLens 上门控对指代图片的问题漏判（§8.3）；
  - 看图增益相加后截断，L1 + 看图与 L2 + 看图打平（§5.3）；
  - "各档准确率"按主回答模型标定，换了回答模型就不准（§6）。

  N11 在开发集上做了控制器 v2，测试集只作事后重放（§12.1）：前两条有小幅改善（MemLens 32K 60.0% → 62.6%），第三条重新标定无效，按回答模型调 λ 有效。
- **混合流是构造的。** 与记忆无关的查询来自 Dolly 的通用请求与生成的同话题问题，"20% 是记忆题"是假设。N11 用 WildChat 里真实用户消息的第一句检验了门控的误召回（§12.1），但记忆题在真实流量里占多少、长什么样，仍然没有数据。
- **标准答案有噪声。** 人工抽查的错题里，LoCoMo 有 10 / 40 是标准答案有误或推不出（时间题 7 道里占 5 道），MemLens 有 2 / 40 与会话日期矛盾。这些题没有剔除。
- **LongMemEval 的会话 ID 泄漏**（N12 查出，D-067）。检索类方法的回答模型能从会话 ID 认出证据会话。消融（B2、L1、L2、控制器与 Mem0）没有测出它对 CueMem 的影响，但每臂只跑一次，B3、B6a 没有做消融，控制器的准确率表与 λ 也是在泄漏下的结果上拟合的（§3.5）。
- **大模型一档没有跑。** deepseek-v4-pro 那一档因 DeepSeek 账户余额不足没有跑，H3 只覆盖小、中两档。
- **数据集都是英文的**，中文对话没有评测；小模型（qwen3.6-35b-a3b）的价格按 OpenRouter 的参考价记（D-049）。
- **运行中断。** 失败的请求不留下任何结果，补跑与一次跑完等价。中断有三次：
  - DeepSeek 账户余额在 LoCoMo 测试集跑到约四分之三时用完，之后的请求全部失败（不进缓存），充值后用同样的配置续跑。
  - qwen3.6-35b-a3b 的调用限额很紧，8 路并发时约三分之一的请求被限流，降到 2 路补跑。
  - test400 里有一个会话，qwen3.8-flash 抽取时生成失控，三个小时里重试 5 次都超时（每次 4 个请求、各等 120 秒）；这道题因此最后才跑完。超时与内容审核一样，本应换备用模型：为此给结构化输出加了超时回退（D-050）。加了回退之后重建，qwen 第一次请求就正常返回了，回退没有触发。

### 10.2 教训

1. **先把写入和读法做好，再做路由。** 最大的收益来自写入路径（LongMemEval +9 个点）和"先记笔记再回答"（LoCoMo 上 L1 +3.1 个点、比任何路由都划算）。控制器的价值在"要不要想起"（混合流省 41%），没有提高纯记忆题的准确率。如果重来，会更早把 L1 的默认读法改成先记笔记。
2. **标签与评估都要防"回答的随机翻转"。**
   - 事后理想路由与固定档位的差距，大部分是翻转。
   - N7 用推理类型作中介标签，开发集的估计在测试集上复现了（81.2% → 81.6%）。
   - 补检索在开发集上的 +4 / −0 在测试集上没有复现（+2 / −3），是同一个教训。
3. **冻结的测试集换来可信的数字，代价是发现的问题不能回头修。** MemLens 上的看图增益饱和，本可以在 N7 发现：只要把各动作的预测成功率按数据集画出来，就能看到两档同时被截成 1.0。
4. **回答模型的能力是一个会变的参数。** 控制器的"各档准确率"要随回答模型标定；"让模型自己检索"好不好，取决于这个模型会不会用工具。部署时控制器要能用少量在线标注重新标定，N7 里 20 条目标数据就补回了跨数据集的迁移。
5. **本地缓存让评测可复现、可审计。** 请求逐字相同才命中缓存，所以控制器的真实运行能与离线重放逐题核对；失败的请求不进缓存，所以余额用完、限流、超时之后续跑，与一次跑完等价。
6. **先审一遍数据集。** 绝对准确率与他人的数字比较时要谨慎：LoCoMo 的时间题有不少标准答案本身就错，MemLens 有叙述顺序与会话日期矛盾的题。

### 12.1 控制器 v2

两处改动，门控、推理类型模型与 λ（仍是 30）都不变（D-052）：

### 12.3 判分与随机性

**换一个判分模型。** deepseek-flash（另一家的模型，提示与解析相同）重判 N9 主要方法的 12,835 条回答：

| 数据集 | 一致率 | κ | 判对的比例：主 / 第二 | 方法排序 Kendall τ |
|---|---|---|---|---|
| LongMemEval | 97.9% | 0.91 | 87.3% / 87.9% | 0.90 |
| LoCoMo | 94.7% | 0.82 | 80.9% / 84.4% | 0.90 |
| MemLens 32K | 96.8% | 0.93 | 58.1% / 61.4% | 0.87 |
| MemLens 128K | 96.7% | 0.93 | 56.8% / 59.6% | 1.00 |

17 组关键对比只有一组的显著性变了：LoCoMo 上 L1 低于全上下文，+65 / −92（p = 0.038）→ +64 / −77（p = 0.31）。这是未校正的说法：按每个数据集、每个判分模型的关键对比做 Holm 校正后，主判分下 LongMemEval 的控制器对 L2 与 LoCoMo 的 L1 对全上下文，第二判分下 LongMemEval 的控制器与 B6a 对 L2、LoCoMo 的控制器对 L1，都只是名义显著（`second_judge-holm.json`）。排序的变化都在相邻、相差不到 2 个点的方法之间。第二判分处处更宽松；它也是主回答模型，可能偏向自己的回答，所以只用来检验结论，不替换主判分。

**同一配置再跑一遍。** 关掉 LLM 缓存，在同样的记忆空间上重跑：

| 数据集 | 方法 | N9 | 重跑 | 逐题翻转：对→错 / 错→对 |
|---|---|---|---|---|
| LongMemEval | L1 | 90.5% | 90.0% | 7 / 5（3.0%） |
| | 控制器 | 90.5% | 90.2% | 8 / 7（3.8%） |
| LoCoMo | L1 | 79.7% | 80.5% | 16 / 26（3.6%） |

温度为 0，回答文字仍有一半以上不同；准确率在 ±1 个点内波动，3–4% 的题会翻转。**相差 1 个点左右的比较都不是稳定的结论**：LoCoMo 上"L1 比全上下文低 2.3 个点"重跑后缩小到 1.5 个点、换判分后不显著，应看作两者接近；LongMemEval 上控制器对 L1 的 10 / 10 也是如此。差得多的结论（LongMemEval 上 L1 对全上下文 +84 / −14、控制器对 L2）远在波动之外。重跑是在同样的记忆空间上做的，不包括写入路径的随机性，所以这个波动幅度是下限。

人工抽检：从 N9 的判分里按数据集分层抽了 50 条（LongMemEval 15、LoCoMo 15、MemLens 20，判对、判错各半，`scripts/n11_audit.py`），逐条人工核对。勾选的 48 条全部同意判分（48 / 48，95% 置信区间下限约 93%）；另外 2 条 LoCoMo 题没有勾选，两个判分模型都判它们为错。第二判分模型也判过其中 44 条，与主判分 42 条一致；不一致的 2 条都是 LoCoMo 的列举题，回答漏了标准答案里的一项：主判分按官方规则（只答出一部分算错）判错，第二判分判对，人工核对站在主判分一边。样本小，只能说明没有发现明显的误判，与两个判分模型之间 94.7–97.9% 的一致率相符。

### 12.4 写入路径与遗忘

- **对账提示分清"范围不同""现实变了""说错了"，并附上原话**（D-053）：修 N9 错误分析里的两个错误（"周五 6 点起"取代了"工作日 6 点半起"；"搬到新加坡"被标成"更正"）。联网测试发现只改提示不够：对账模型只看到抽取出的"Mia 31 岁"，分不清是用户更正还是过了生日，所以灰区里每条新事实附上它出自的那句话。同一段新编对话重复 5 次，范围不同 / 现实变了 / 说错了都是 5 / 5（N9 的提示：3 / 5、5 / 5、0 / 5）。只是一段对话、提示又是对着它改的，不代表对账的整体准确率。提示文本不在巩固指纹里，已有的评测空间不会重建。
- **Agent 的回答缓存按会话归属**（D-054）：遗忘只清受影响会话的缓存，演示回放不再因为别的会话被清缓存而偶发失败。两次完整回放都是 14 项过 13 项，遗忘之后的检查都通过；没过的两项一个是关键词检查太死（回复守住了素食约束但没写"vegan"，已放宽），一个是 Agent 把上一题又答了一遍（对账结果正确，之前 3 次回放都通过）。后来查明不是随机失误：控制器给这道预算题附了照片，见 §12.1 的控制器 v3。
- **遗忘留下的空缺在重新抽取时标出来**（D-059）：删掉出处那一轮后，"我给她买了"被重新抽成"给 Lena 买"（重建后抽 12 次，12 次都是）。发言编号不复用，空缺就是编号不连续的地方：重新抽取时标出 `[deleted]`，并说明挨着空缺的代词不要套到别人身上，8 次都写成"给某人买"。只有删过发言的会话请求会变，评测空间的抽取缓存全部有效。

### 12.5 规模与部署

离线延迟基准（`scripts/n11_latency.py`，哈希向量器，不含线上约 110 ms 的查询向量化；Apple M2，每档 3 次取中位数）：

| 轮数（检索单元） | 读路径 p50：本地模式 | 读路径 p50：Qdrant 服务端 |
|---|---|---|
| 500（1.3k） | 32 ms | 14 ms |
| 2,000（4.7k） | 111 ms | 20 ms |
| 8,000（1.9 万） | 445 ms | 33 ms |

- 本地模式是 Python 实现的精确检索，随规模线性增长；一年每天聊一次约 3,600 轮，本机部分约 0.2 秒。再大就该换服务端（建了 payload 索引）。

## 13. N12：同协议的外部对比

### 13.3 换模型：Graphiti 与 LangMem 对抽取模型很敏感

从 pds 换到 pq，CueMem L1 / L2 是 82.5% → 81.5%、87.0% → 85.0%，Mem0 81.0% → 77.5%，Cognee 77.5% → 74.0%；Graphiti 与 LangMem 则大幅下降。

两个协议之间回答模型与判分也换了（全上下文 84.5% → 80.0%；N11 用 deepseek-flash 重判 N9 的 LoCoMo 回答，判对的比例是 84.4%，qwen3.8-max 是 80.9%，§12.3），几个点的升降说明不了写入的好坏。Graphiti 与 LangMem 的大幅下降在写入上有直接证据：

- **Graphiti：59.0% → 41.5%。**
  - qwen3.8-flash 用 Graphiti 自己的提示抽出的实体少得多：7 段对话合计 1,253 → 462 个，事实 3,426 → 1,774 条。
  - 事实要挂在实体上，挂不上就丢掉：pq 下每段对话记下 118–270 次 "Target entity not found"，pds 下每段只有 4–15 次。
  - pq 下的发言召回（任一：检索结果里至少有一条包含证据发言的题所占的比例）只有 54.5%（朴素检索 84.5%，CueMem L1 95.0%）。各方法交给回答模型的条数不同，召回只能看大致高低。
  - 向量这一路并没有空（pq 下每题的事实候选中位数是 8 条），所以 Graphiti 默认的 0.6 相似度阈值保持不变，没有重调。
- **LangMem：78.0% → 30.0%。**
  - 通义用 PatchDoc 把新信息并进少数几条长记忆：7 段对话的记忆从 705 条降到 123 条。
  - 丢了写入的会话从 2 / 202 增加到 23 / 202；另有 5 个会话通义明说"不用改"，回了空的 PatchDoc。读不出的 PatchDoc 补丁也算丢了写入。
  - 原来的写入检查在超过 max(2, 10%) 的会话丢写入时作废整份写入，pq 下 7 段里有 4 段过不了。两个协议的完整运行都放宽到 25%（`CUEMEM_LANGMEM_MAX_LOST_SHARE=0.25`，默认仍是 10%），丢掉的写入照实记录。
- **Cognee 两个协议下的写入都没有出问题**：没有失败、重试或丢掉的会话。
- **A-MEM 在两个协议下差不多**（k = 10：58.0% → 59.5%；k = 40：75.0% → 65.0%）。pds 下 deepseek-flash 的演化回复常写到 4096 tokens 的上限，124 次演化因此放弃（pq 下 4 次）。

外部系统的提示是按它们默认的模型写的，换了抽取模型，分数可能变很多。pq 下 CueMem 又占着主场，所以对外部系统的判断以 pds 为准。

### 13.4 局限

- **只有一个数据集，每个配置一次。** 200 题上相差几个点的比较（比如 L1 对 Mem0）都在波动之内：N11 的重跑里准确率在 ±1 个点内波动、3–4% 的题翻转（§12.3）。配对检验以每个系统的一次写入为条件；N11 的重跑在同样的记忆空间上做，不包括写入路径的随机性，而写入正是 Graphiti、A-MEM 这类系统随机性最大的部分，所以这个波动是下限。写入的重复运行、按对话分簇的 bootstrap 都没有做（D-069）。LongMemEval 上的外部对比只有 Mem0：N11 的数字在泄漏下（§12.2），修复后在 test100r 上重跑过一次，L1 90.0% 对 Mem0 79.0%（§3.5）。
- **判分与回答模型同源**（§13.1）。
- **不是各系统的默认用法。** 外部系统换成了 DeepSeek / 通义的模型与向量，回答交给同一个回答模型与提示，不用它们自己的回答提示；论文与官方报告里的数字（不同的模型、回答与判分）不能直接比。
- **为了跑通，适配层加了几处处理**：
  - 回复是 JSON 但不合 schema 时重新采样（Graphiti、A-MEM）；
  - 被内容审核拒绝的发言跳过并计数：pq 下 Graphiti 的 conv-42 有 5 条（写入时还没加上 qwen3.7-plus 备用模型），其余六段 0 条；
  - LangMem 丢写入的会话按 25% 的上限放行并记录（§13.3）。
- **Graphiti 与默认用法的差异**：BFS 深度用 1 而不是 3（Kuzu 的可变长路径查询在深度 3 时超过 12 GB 内存）；pq 下事实用 qwen3-rerank 重排，pds 下没有重排模型，走 RRF。
- **刻意没调的**：Graphiti 的相似度阈值、LangMem 的提示、A-MEM 的 k（主结果用论文的默认 10；作者给 GPT-4o 级模型的 k = 40 另做了敏感性运行，§13.2）。
- **Cognee 的上下文不设上限**：照它的 BEAM 报告，20 块、20 个实体、5 条事实全部交给回答模型，每题回答的输入平均 5,683 / 6,689 tokens（pds / pq），L1 是 4,333 / 5,034。
