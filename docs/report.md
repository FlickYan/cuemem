# CueMem 技术报告

> v1.0 · 2026-10-13 · N9 · [English](en/report.md)。本文汇总整个项目的设计与最终评测；各节点的细节与开发集上的实验见 [docs/results/](results/)，设计取舍见 [decisions.md](decisions.md)。

## 摘要

CueMem 是一个给 LLM Agent 用的长期记忆系统，由四部分组成：

- **写入**：原始日志不可变，异步巩固出带有效期的事实。
- **检索**：三档（L0 只给画像、L1 快速召回、L2 深度检索）。
- **控制器**：一个不调用 LLM 的检索控制器，决定每一问"要不要想起、想多深"。
- **多模态**：回答时把原图取回来再看一遍。

最终评测在三个测试集上进行：LongMemEval test400、LoCoMo 后 7 段对话（1,155 题）、MemLens 195 题。方法与配置事先冻结，测试集只用一次。

- **记忆系统比全上下文又准又便宜**：LongMemEval 上 L1 90.5% 对 73.0%，成本约 1/20；MemLens 128K 上 L2 + 再感知 65.1% 对 46.2%。
- **写入路径是最大的单项收益**：朴素检索加上写入路径的产出，LongMemEval 82.0% → 91.0%。
- **冻结的控制器在测试集上复现了开发集的估计**（记忆题 81.2% → 81.6%）。在 20% 记忆题的混合流里，它比"总是检索"便宜 41%、准确率不降；但在纯记忆题上始终低于总是 L2（合并低 2.8 个点）。它的价值在"要不要想起"，不在"想多深"。
- **让模型自主检索（ReAct）各有所长**：文字记忆上最强（LoCoMo 85.5%），图片记忆上失灵（MemLens 46.7%）。"控制器先选、模型兜底"在三个数据集上都稳，但最贵。
- **真正"检索没取到"的错题很少**：多的是控制器选错档、计数漏数，以及 LoCoMo 标准答案本身的问题（抽查的 40 道错题里有 10 道）。
- **所有数字都能从本地缓存一键重放**，控制器的真实运行与离线重放逐题一致。

## 1. 问题

LLM Agent 要在跨越数月、上百个会话的交互里**记得住、想得起、记得准**：用户说过的偏好、计划、换了的工作与预算、分享过的照片，都要在之后某一天被问到时答得出来，而且答的是最新的那个版本。

把全部历史塞进上下文不是答案：成本随历史线性增长，模型对长输入里的信息用得越来越差（LongMemEval、Lost in the Middle），而且新旧说法并存时要靠模型临场判断。本项目把记忆当作信息管理问题来做，并回答一个具体问题：**"这一轮要不要想起、想多深"应该由谁决定**——让 LLM 自己调用检索工具，还是由一个便宜、可训练、可度量的控制器决定。

## 2. 系统

```text
用户消息 ──► 记忆探针（不调用 LLM，几十毫秒）──► 检索控制器 ──► L0 只给画像
                                                        ├──► L1 快速召回（不调用 LLM）
                                                        └──► L2 深度检索（规划、补检索、记笔记）
                                                              （有图时再决定要不要附原图）
         ──► 在线写入（原始日志、向量、原图）──► 后台巩固（事实、实体、有效期、画像、图片描述）
```

### 2.1 写入：原始日志 + 异步巩固（N3）

- **原始日志不可变**，是唯一的事实来源。在线写入只追加发言、建向量索引、存原图（按内容哈希），不调用 LLM。
- **巩固**在后台按会话进行：抽取原子事实与实体（qwen3.8-flash）、实体消歧、事实对账、会话摘要、图片描述、核心记忆（画像）。派生记忆全部可以从日志重放。
- **双时间轴有效期**：事实带事件时间（valid_from / valid_to）与记录时间（recorded_at / invalidated_at）。"我搬到新加坡了"（现实变了）与"我说错了，其实是上海"（认知变了）都让旧事实失效，但含义不同；旧事实保留，问"以前"时还答得出来。
- **对账**：规则只管合并、否定与多值累积，"取代"一律由 LLM 确认。首轮按规则取代的精确率只有约 10%，错误的"已失效"标签比没有更糟（D-019）。
- **遗忘**：从日志删除 + 用剩下的日志重放派生记忆 + 按归属清理缓存（D-021）；N8 起以整轮为单位、沿引用扩散（D-046）；N10 起还会在原始日志里找没有引用、只是转述了它的轮（D-051）。

### 2.2 读取：三档检索（N4、N5、N7）

| 档 | 做法 | 额外的 LLM 调用 |
|---|---|---|
| L0 | 只给常驻上下文（核心记忆 / 画像） | 无 |
| L1 | 轮、事实、摘要、图片描述多路 dense 召回，模态内取最大、模态间 RRF；时间表达加分；按 token 预算（4k）打包，每条证据标"距提问几天" | 无（一次查询向量化） |
| L2 | 查询规划（子查询、时间区间）→ 多查询"取最好名次"融合 → 充分性检查与补检索 → 先记笔记再回答 | 2–4 次便宜模型调用 |

L1 的设计由纯检索指标调出：按 token 预算打包是最大的单项杠杆（LoCoMo 一轮只有一句话，固定取 10 轮会少掉四分之三的上下文，D-029）；换向量模型（text-embedding-v4 → qwen3.7-text-embedding）的收益超过所有检索技巧（D-014）。L2 里最大的杠杆是"先记笔记再回答"，图扩散与重排实现了但实测无益，默认关闭（D-030 至 D-032）。

### 2.3 检索控制器（N7）

- **记忆探针**：一次 L1 打分（选了 L1 时候选直接复用），产出 54 个特征：问题线索（第一人称、指向过去的对话、时间与聚合表达、视觉词……）、检索分数分布、命中的分散程度与时间跨度、被取代的事实、实体与图片命中、记忆规模。
- **两段式控制器**：门控估计"这一问与记忆无关"的概率，推理类型模型（七类）估计是哪类记忆题；查"这类题在各档上的准确率"，按 P̂(答对) − λ · 成本选动作（L0 / L1 / L2，有图时 ± 再感知）。标签用推理类型作中介，而不是逐题的"答没答对"——后者被回答的随机翻转污染（D-038）。
- **λ 是业务旋钮**："多答对一题愿意多付多少钱"；默认 λ = 30 按"不比总是检索差的前提下最省钱"事先选定（D-040）。参数导出成 JSON，运行时两次矩阵乘法。

### 2.4 多模态（N6）

图片的三种表示：原图（按内容哈希存放）、图文同空间的视觉向量（以文搜图、以图搜图）、两种描述（结合对话上下文的、只看图的）。描述填回原话参与事实抽取，也作检索键。**回答时再感知**：附上最相关的 3 张原图——存储时压缩换长度稳定，回答时取回原图换视觉保真（D-003、D-037）。

### 2.5 Agent Runtime（N8）

自研的对话循环：控制器先选档召回，模型可以用 `memory_search` 自己补查（D-042）；上下文按分区预算装配，系统提示、画像快照、本次对话的原话组成稳定前缀，召回的记忆只放在最后一条消息里（D-043）；每轮在线写回，会话结束后台巩固（D-045）。另有 FastAPI 接口、可解释的 Gradio 界面（记忆轨迹面板、记忆浏览器）与 MCP Server。

## 3. 评测设置

### 3.1 数据与划分

| 数据集 | 测试集（N9 才使用） | 开发集（N2–N8） |
|---|---|---|
| LongMemEval_S（每题约 48 个会话、11.5 万 tokens） | test400 | dev100（另有 pilot10 试跑） |
| LoCoMo（10 段两人长对话，不评对抗题） | 后 7 段对话，1,155 题 | 前 3 段对话，385 题 |
| MemLens（图文交错，80% 的题需要图片证据） | 官方 195 题记忆智能体子集，32K 与 128K 两档 | 子集外分层抽的 100 题（32K） |
| 混合流（与记忆无关的查询，N7 构建） | 测试集版：Dolly 里与开发集不重叠的 1,750 条 + 为每道测试题生成的同话题常识问题 | 开发集版：585 + 585 条 |

测试集上要比较的方法、控制器（N7 导出的模型、λ = 30）、检索与提示词在看测试集之前就固定了；N9 只新增了一个方法 B6a（N8 的 Agent 做法，在看测试集之前定义）。

### 3.2 方法

| 编号 | 方法 |
|---|---|
| B0 | 无记忆 |
| L0 | 只给核心记忆（画像） |
| B1 | 全上下文：把整份历史塞给长上下文模型（MemLens 上图片按原位插入） |
| B2 / B2F | 朴素检索（dense top-10）/ 同样的检索 + 写入路径的产出（事实增强键、带有效期的事实、画像） |
| B4-nobm25 | L1 快速召回（下文简称 L1） |
| B4-note | L1 + 先记笔记再回答 |
| B5 | L2 深度检索 |
| B6r / B6 / B6h / B6z | 规则版控制器 / 学到的控制器（λ = 30）/ 门控拿不准时问 LLM / 零样本 LLM 路由 |
| B3 | 模型自主检索（ReAct：`memory_search`、`date_diff`，最多 5 步） |
| B6a | 控制器先选、模型兜底：B6 召回的记忆随问题给出，模型缺什么再用 `memory_search` 补查 |
| ORACLE | 只给标注的证据会话（上限参照，不可部署） |

MemLens 上 L1、L2 另有再感知版本（B4-see、B5-see），B4-mm 是不附原图的 L1。

### 3.3 回答模型与判分

- 主回答模型 deepseek-flash（关闭思考模式，能读图）；判分 qwen3.8-max，与主回答模型不同家族（D-008）。判分提示词逐字照搬 LongMemEval 官方模板（LoCoMo 沿用同一模板，D-015）与 MemLens 官方提示词（D-034）。
- 换回答模型（H3）：小模型 qwen3.6-35b-a3b（混合专家，每次激活约 3B 参数）、qwen3.8-flash、大模型 deepseek-v4-pro（因账户余额未跑，见 §6），在 `test100r`（test400 分层抽 100 题）与 `test200r`（LoCoMo 测试集分层抽 200 题）上评测。qwen3.8-flash 与判分模型同一家族，它和其他回答模型之间的绝对准确率不能直接比，同一回答模型下方法之间的比较仍然有效。

### 3.4 成本与统计

- 成本统一按名义标价（高峰时段、未命中缓存）计算，便于不同时间跑的实验比较；实际花费（扣除本地缓存命中、供应商缓存折扣、DeepSeek 错峰半价）单独统计（D-010）。DeepSeek 的调用全部放在非高峰时段（D-024）。
- 置信区间用 bootstrap（95%）；同一批题上两种方法的比较用配对符号检验（只看"一个对、一个错"的题）。
- 本地响应缓存让每个结果都能免费重放：控制器类方法选中的那一档与固定档位的请求逐字相同，直接命中缓存——所以"B6 的真实运行"与"冻结模型的离线重放"可以逐题核对。

- **记忆系统与全上下文。**
  - LongMemEval：L1 比全上下文高 17.5 个点（+84 / −14），成本约 1/20。全上下文在多会话题（62.9%）和时间题（52.0%）上最差。
  - LoCoMo：每段对话约 2 万 tokens，全上下文本身不长。L1 低 2.3 个点（p = 0.038），L2 高 2.5 个点（p = 0.021），成本不到一半。
  - MemLens：全上下文从 32K 到 128K 掉了 5.6 个点；L2 + 再感知几乎不变（65.6% → 65.1%），对全上下文 +33 / −6、+47 / −10。
- **写入路径。** 同样的朴素检索，加上写入路径的产出（带有效期的事实、事实增强的检索键、画像），LongMemEval 82.0% → 91.0%（+53 / −17，p < 0.001），多会话题与时间题各高约 16.5 个点。在这之上，L1 的检索改进在 LongMemEval 上没有再挣到（90.5% 对 91.0%，+9 / −11），LoCoMo 上比朴素检索高 11.5 个点（+168 / −36）。
- **L2 对 L1。**
  - LoCoMo：+4.8 个点（+76 / −20，p < 0.001），多跳、开放推断、时间、单跳四类各自显著。N5 在开发集上没达到的"分题型显著"，在测试集上达到了。
  - LongMemEval：+2.7 个点（p = 0.071）。
  - MemLens（带再感知）：32K +2.5 个点（n.s.），128K +9.7 个点（p < 0.001）。
  - L2 的代价：成本约为 L1 的 2.1–2.3 倍；LongMemEval 的拒答题上 L2 比 L1 少对 4 道，检索得越深，越容易找到"沾边"的内容而作答。
- **模型自主检索。** B3 在 LoCoMo 上是最好的方法，LongMemEval 上与 L2 相当（+9 / −14，n.s.），MemLens 上只有 46.7%。它的检索工具只返回文字，信息抽取题只对 24.6%，错题里 58 道是误拒答。B6a 先用控制器召回（可以附原图），模型再补查，三个数据集都不差，代价是最贵。
- **ORACLE 不是上限。** 它只给原始的证据会话，没有结构化事实、日期标注和笔记，在 LongMemEval 与 MemLens 上低于 L2。

## 5. 检索控制器在测试集上

### 5.1 开发集的估计在测试集上复现了

N7 的数字是开发集 585 题上按对话历史交叉拟合的估计；测试集上用的是导出的冻结模型。三个测试集的记忆题合并是 1,750 道（MemLens 只计 32K），混合流按记忆题占 20% 加权。

| 策略 | 记忆题：开发集（交叉拟合） | 记忆题：测试集（冻结） | 混合流每千条成本：开发 → 测试 | 误召回：开发 → 测试 | 漏召回：开发 → 测试 |
|---|---|---|---|---|---|
| 总是 L1 | 80.5% / $1.57 | 80.3% / $1.53 | $1.57 → $1.53 | 100% → 100% | 0 → 0 |
| 总是 L2 | 85.3% / $3.46 | 84.4% / $3.42 | $3.46 → $3.42 | 100% → 100% | 0 → 0 |
| B6r 规则版 | 82.6% / $2.01 | 81.4% / $2.07 | $1.92 → $1.95 | 100% → 100% | 0 → 0 |
| B6z 零样本 LLM 路由 | 80.7% / $2.15 | 80.3% / $2.23 | $0.72 → $0.74 | 0.4% → 0.8% | 5.3% → 3.0% |
| B6h 拿不准时问 LLM | 80.2% / $2.21 | 81.3% / $2.41 | $0.80 → $0.85 | 10.3% → 11.0% | 3.9% → 1.8% |
| **B6（λ = 30）** | **81.2% / $2.14** | **81.6% / $2.36** | **$0.87 → $0.90** | 19.2% → 17.3% | 2.4% → 1.1% |

- **混合流里，B6 比"总是检索"便宜 41%，记忆题准确率还高 1.3 个点**（开发集估计 45%）。区分记忆题与无关查询的 AUC 是 0.990（开发集 0.983）；探针 p50 163–487 ms，取决于记忆空间的大小。
- **纯记忆题上，它夹在两个固定档位之间**：对总是 L1 +60 / −37（p = 0.025），对总是 L2 +15 / −64（p < 0.001）。H2 的结论与 N7 相同：混合流那一半成立，纯记忆题那一半不成立。
- **B6 与零样本 LLM 路由仍是各有所长**：B6z 几乎不误召回，但漏掉 3% 的记忆题，且每问多一次调用；B6 不调用 LLM，漏得更少，17% 的无关查询仍去检索。
- **真实运行与离线重放逐题一致**：400 / 400、1,155 / 1,155、195 / 195 × 2。控制器选中的那一档与固定档位的请求逐字相同、命中缓存，所以上表的每个策略都是"冻结模型 + 各档的真实结果"。

| LoCoMo | 79.7% / $1.44 | 84.5% / $3.25 | 80.6% / $1.69 | 82.2% / $2.21 | L0 上 1 道，L1 上 33 道（赢回 7 道） |
| MemLens 32K | 63.1% / $1.96 | 65.6% / $4.41 | 63.6% / $2.73 | 60.0% / $3.14 | L0 上 5 道，L1 上 8 道（赢回 2 道） |
| MemLens 128K | 55.4% / $1.94 | 65.1% / $4.43 | 57.9% / $2.70 | 60.5% / $3.61 | L0 上 4 道，L1 上 7 道（赢回 2 道） |

- **LongMemEval 上 B6 没有赢过总是 L1**：+10 / −10，成本高 51%。门控把 7 道题放到了 L0，其中 6 道答错（换 L1 都能答对），抵掉了 L2 挣来的部分。规则版 B6r 反而更好（+12 / −4，p = 0.077），它的线索词正好覆盖 LongMemEval 的多会话题与时间题（N7 已经观察到）。
- **LoCoMo 上 B6 比规则版好**（+34 / −16，p = 0.015），规则在多跳题上几乎不触发。
- **"L1 + 先记笔记"仍比任何路由都划算**：LongMemEval 91.8% / $1.86、LoCoMo 82.8% / $1.70，比 B6 准也比 B6 便宜（两个数据集合并 +56 / −44，n.s.）。N7 的这条结论在测试集上也成立。

### 5.3 MemLens 上的一个设计缺陷：看图增益饱和

控制器在有图的空间里估计"L1 + 看图""L2 + 看图"的成功率时，把这类题的看图增益加到不看图的成功率上，再截断到 1.0（`action_proba`）。开发集上看图的增益很大，加完之后两档常常都被截成 1.0，排序信息丢了，代价项就总选便宜的 L1。

| MemLens 32K 上 B6 的选择 | 题数 | B6 | 总是 L1 + 看图 | 总是 L2 + 看图 |
|---|---|---|---|---|
| L0 | 11 | 2 | 8 | 7 |
| L1 + 看图，两档都被截成 1.0 | 49 | 36 | 36 | 41 |
| L1 + 看图，没有截断 | 22 | 20 | 20 | 20 |
| L1 不看图 | 4 | 3 | 3 | 4 |
| L2 + 看图 | 109 | 56 | 56 | 56 |

B6 输给总是 L2 + 看图的 13 道题里，6 道在"被截断"那一组，5 道是门控把记忆题放到了 L0（多是指代已分享图片、没有第一人称线索的问题，N7 的零样本 LLM 路由也漏这类）。改法很直接：看图增益改在对数几率上相加，或者在截断前比较。但测试集上发现的问题这次只记录、不回头改（D-048）。

- **大模型一档（deepseek-v4-pro）没有跑。** DeepSeek 账户余额不足，运行脚本停在了这一步之前。命令在 `scripts/reproduce.py` 里，标为可选步骤（没有缓存、名义成本约 $17），加 `--with-optional` 才执行。

|---|---|---|---|---|---|
| 写入路径（B2F 对 B2） | LongMemEval | 91.0% / 82.0% | +53 / −17 | p < 0.001 | 多会话 +16.5、时间 +16.7、知识更新 +10.5 个点 |

| 再感知（L1 + 看图对 L1） | MemLens 128K | 55.4% / 48.7% | +18 / −5 | p = 0.011 | 信息抽取 +15 / −1 |

- **写入路径的收益最大，有效期标签的收益最小。** 知识更新题上，完整版与两个消融都是 96.5%（55 / 57）：原始对话仍在上下文里，模型靠原话就能分辨新旧（H4 未得到支持）。完整版对两个消融的优势来自多会话题（+10 / −5），不显著。"只给当前事实"会丢掉被取代的历史，计数类问题因此吃亏。
- **"先记笔记再回答"是最有效的读法**，在 L1 上（LoCoMo）和 L2 上（LongMemEval 的时间题）都是如此。
- **补检索在测试集上白花钱。** N5 的开发集上它救回了 4 道散落在多次对话里的计数与时间题（+4 / −0），测试集上没有复现（+2 / −3），成本却多 30%。开发集上 100 题里的 4 题，本来就在回答翻转的量级之内。
- **图扩散在测试集上仍然没有用**，与 N5 一致：对话抽取出的实体图太"星形"，扩散不出新东西（D-031）。重排在 N5 就关掉了，这次没有再测。

## 8. 错误分析

分两层：

- **自动归因**：按规则给全部错题分类（控制器没检索 / 误拒答 / 检索未命中 / 命中而 ORACLE 答对 / ORACLE 也答错）。
- **人工标注**：从 B6（默认部署的做法）的错题里按题型分层抽 40 道逐题看（LongMemEval 只错 38 道，全看），标注成 11 类。定义见 `scripts/n9_errors.py`；标注只存题号与标签，在 [error_labels.json](results/n9-final/error_labels.json)。看图题的错题还核对了回答时附的原图里有没有证据图。

"控制器选错档"的口径有三种情况：

- 记忆题被放到了 L0；
- 选了 L1，换 L2（附图与否不变）就能答对；
- 该附原图却没附。

反过来"选了 L2 答错、L1 能答对"不算，那是 L2 自身的波动。

| 人工标注 | LongMemEval（38 / 38） | LoCoMo（40 / 206） | MemLens 32K（40 / 78） |
|---|---|---|---|
| 控制器选错档 | **16** | 3 | **9** |
| 计数 / 求和 / 列举 | 9 | **10** | 6 |
| 标准答案有误或推不出 | 3 | **10** | 2 |
| 日期推算 | 3 | 1 | 2 |
| 用了过时的版本 | 2 | — | 1 |
| 误拒答 | 2 | 2 | 5 |
| 判分过严 | 2 | 4 | 5 |
| 证据没进上下文 | 1 | 5 | — |
| 推理或理解 | — | 5 | 2 |
| 看错图 | — | — | 8 |

三个数据集共同的结论：

- **真正"检索没取到"的很少。**
- **多的是三类问题**：控制器选错档、计数漏数，以及数据集本身的问题。
- **"编造"一道也没有出现。**

### 8.1 LongMemEval：最大的一类是选错档

| 类型 | 题数 | 例子 |
|---|---|---|
| 控制器选错档 | 16 | 门控把 6 道记忆题放到了 L0，换 L1 全部答对。这些问题没有"我上次说过"之类的线索，例如"我们公司的领导岗位里女性占百分之几？""西红柿和万寿菊哪个先播种？"。另 10 道选了 L1、L2 能答对，例如"洒红节和圣玛丽教堂的周日弥撒隔了几天"：L1 拿到了两个日期（2 月 26 日、3 月 19 日）却算成 7 天，L2 答对了（21 天） |
| 计数 / 求和 / 列举 | 9 | "今年参加了几场婚礼"答 5 场，应为 3 场：把姐姐的婚礼和"九月戴项链的那场"也算了进去。"六座博物馆的先后顺序"漏掉了最早的科学博物馆 |
| 标准答案有误或推不出 | 3 | "流感好了之后过了几周跑了第十次步"：1 月 19 日到 4 月 10 日是 11.6 周，标准答案是 15 周 |
| 日期推算 | 3 | "我几周前去了 Summer Nights 节"答 6 周，应为 3 周 |
| 用了过时的版本 | 2 | "我现在把旧球鞋放在哪"答"床底下"，后来的会话说放到了衣柜的鞋架上 |
| 误拒答 | 2 | 七点出门、路上两小时，"几点到的诊所"答"不知道" |
| 判分过严 | 2 | 标准答案"澳大利亚的墨尔本大学"，回答"墨尔本大学" |
| 证据没进上下文 | 1 | |

- **选错档的 16 道里，L1 → L2 的 10 道集中在多会话计数与时间推算。** 这正是 L2 的笔记擅长的；另有 3 道是偏好题。
- **门控漏判的比例与开发集的估计一致。** LongMemEval 上 B6 把 7 道题（1.8%）放到了 L0，6 道答错；三个测试集合并的漏召回是 1.1%，开发集估计是 2.4%。
- **记忆的有效期标错了一次。** 对账把三条范围不同的起床时间串成了一条新旧链："工作日 6 点半" → "每天 7 点半" → "周五 6 点"。问"周五比其他工作日早起多久"时，模型看到"工作日 6 点半"已被标为作废，只好给出两个条件答案。范围不同（工作日 / 每天 / 周五）的事实不该互相取代，这是 D-019 讨论过的那类错误。

### 8.2 LoCoMo：标准答案有不少问题

| 类型 | 题数 | 例子 |
|---|---|---|
| 计数 / 求和 / 列举 | 10 | "Deborah 收到过哪些礼物"漏了朋友写给她的那句格言；"Nate 带乌龟散过几次步"答 1 次，应为 2 次 |
| 标准答案有误或推不出 | 10 | 年份写错：2024-01-10 的会话说"昨天"，标准答案是 2023-01-09。天数算错：7 月 11 日出发、20 日回来，标准答案是 19 天。与对话不符："Evan 2023 年的健康状况"的标准答案是"扭伤脚踝"，对话里说的是膝盖。答案只在图片里：问 Audrey 住在哪个州，线索是一张地图照片 |
| 证据没进上下文 | 5 | "Nate 去了哪个州"：他说过"带乌龟去了坦帕的海滩"，检索没取到；模型自主检索（B3）找到了 |
| 推理或理解 | 5 | "Joanna 养什么宠物不会过敏"：对话只说她对有毛的动物过敏，标准答案"无毛猫或猪"要靠常识推 |
| 判分过严 | 4 | 标准答案"goodies"，回答"cookies"（照片里正是一盘饼干） |
| 控制器选错档 | 3 | 选了 L1、L2 能答对 |
| 误拒答 | 2 | 前一次会话说正在普吉岛参加为期几周的静修，这次说"上周五试了潜水课"；问在哪潜的水，答"没说地点" |
| 日期推算 | 1 | |

- **时间题的错多半不是系统的错。** 7 道时间题里有 5 道属于"标准答案有误"。全部 206 道错题里，有 85 道 ORACLE 也答错，问题偏难或有噪声。
- **列举题的标准答案往往很长**，例如 Joanna 做过的 7 种甜点。漏一两样就判错，这是 LoCoMo 多跳题准确率低（B6 64.4%）的主要原因。
- 这些题没有剔除，数字照实报告；与他人报告的 LoCoMo 数字比较时，判分模板与是否修正标注都要注意。

### 8.3 MemLens 32K：找图找得准，看图看不准

B6 错 78 题，人工看了 40 道：

| 类型 | 题数 | 例子 |
|---|---|---|
| 控制器选错档 | 9 | 门控把 5 道记忆题放到了 L0，例如"左边那座金属结构是什么颜色？"：没有"我"、没有指向过去的词，门控以 97–100% 的把握判成与记忆无关。另 4 道选了 L1、换 L2 就能答对，其中 3 道正处在看图增益被截断的那一组（§5.3）。例如 Meal Deal 的价格牌写着 £5，加一杯 £2.50 的奶昔：L1 + 看图答 £5.90，L2 + 看图答对 |
| 看错图 | 8 | 塔上的尖拱数成 2 个（应为 4 个）；风之宫殿中央拱窗右边的窗户是红、蓝、黄的彩色玻璃，答"绿色"；3 道"两段时间哪段更长"的题，地点与时刻只在照片里（街景、钟面），模型没认出来，说"记忆里没提到这个地方" |
| 计数 / 求和 / 列举 | 6 | "在铸铁锅具上一共花了多少"：$105，应为 $225 |
| 判分过严 | 5 | 标准答案"oat bar"，回答"DMI Gourmet Flapjack Original Energy Oat Bars"；回答描述的正是标准答案那张图里的钟，只是叫它"minimalist"而不是"modern" |
| 误拒答 | 5 | "在东京晴空塔与秋叶原站哪段时间更长"：要从会话日期推算，模型说"记忆里没记录时长" |
| 日期推算 | 2 | |
| 推理或理解 | 2 | 把"一开始并不是我最爱的"那一样当成了现在的最爱 |
| 标准答案有误或推不出 | 2 | 见下 |
| 用了过时的版本 | 1 | |

- **找图找得准，看图看不准。**
  - 需要看图的 148 道题里，再感知附上的 3 张原图包含证据图的比例：32K 是 100%，128K 是 96.6%。
  - 排第一的就是证据图的比例：32K 92–95%，128K 82–87%。
  - 可这些题的准确率只有 48–60%。
  - 每道题的证据图平均 4.6 张，"附上任意一张"是宽松的口径，"排第一"更能说明问题。
- **控制器在 MemLens 上的两个问题都出现在错题里。**
  - 门控对"指代已分享图片"的问题漏判：测试集混合流上，MemLens 空间里门控的 AUC 是 0.93，其他数据集都在 0.98 以上。N7 里零样本 LLM 路由也漏这类问题（D-039）。
  - 看图增益饱和，让 L1 + 看图与 L2 + 看图打平（§5.3）。
- **40 道里有 7 道是判分或题目的问题。**
  - 知识更新题有 4 道是同一件东西换了叫法。
  - 另有 2 道标准答案与会话日期矛盾：MemLens 用"At first…"、"Lately…"这样的叙述交代偏好的变化，但会话日期与叙述顺序不一致。例如 05-19 的会话说"最近更偏向 Oculus Quest"，05-26 的会话说"最后还是更喜欢 Switch"，标准答案是 Oculus Quest。按日期取最新的说法（系统的设计，D-002）反而被判错。
  - 这些题没有从统计里剔除，数字照实报告。

## 9. 研究假设的结论

| 编号 | 假设 | 结论 |
|---|---|---|
| H1 | 判断"检索多深"时，探针反馈 + 查询线索特征优于仅用查询文本，也优于基于模型不确定度的触发 | **部分成立**。"要不要记忆"上成立：开发集上只看问题线索的 AUC 0.79、只看探针反馈 0.96、两者合用 0.98；冻结的门控在测试集上 0.990。按模型不确定度逐级升级最差（N7）。"L1 还是 L2"上不成立：推理类型主要看问题怎么问；测试集上 B6 的深度决策比总是 L1 好（+60 / −37），离总是 L2 还差 2.8 个点 |
| H2 | 控制器能在与 always-L2 相近的准确率下显著降低平均成本 | **纯记忆题上不成立，混合流里成立。** 测试集上 B6 比总是 L2 低 2.8 个点（+15 / −64）、便宜 31%；20% 记忆题的混合流里比"总是检索"便宜 41%，记忆题准确率不降（+1.3 个点）。与开发集的估计一致 |
| H3 | 相比模型自主检索，控制器在不同回答模型之间更稳定，在小模型上优势更大 | **不成立**（三个回答模型；大模型一档因余额未跑）。B3 跨模型的波动不比 B6 大；最小的模型上 B3 只在 LoCoMo 上略吃亏（对 L2 +9 / −20，p = 0.061）。控制器自己的问题是"各档准确率"按主回答模型标定，换小模型后照样大量选 L1。"控制器先选、模型兜底"在各回答模型下都不是最差的 |
| H4 | 有效期机制（失效而不删除）提升知识更新类问题，且不损害历史状态类问题 | **未得到支持。** 测试集的知识更新题上，完整版、"只给当前事实"、"不标有效期"三种写法都是 96.5%：原始对话仍在上下文里，模型自己就能分辨新旧。完整版对两个消融的优势（+15 / −6、+13 / −7）来自多会话题，不显著。写入路径整体的收益很大（+9 个点），但不来自有效期标签 |
| H5 | 回答时再感知原图显著提升需要视觉细节的问题，图片 token 成本可由控制器控制 | **成立**（N6；N9 用的是同一个测试集）。L1 附 3 张原图：32K +12.3 个点（+26 / −2）、128K +6.7 个点（+18 / −5），集中在信息抽取题。控制器的确在控制附不附图，但看图增益的截断让它在 L1 + 看图与 L2 + 看图之间选错（§5.3） |
| H6 | 上下文感知的图片描述优于孤立描述，在实体绑定类问题上尤其明显 | **未得到支持**（N6，N9 没有再测）。检索上略好，端到端孤立描述反而多对 3 题（n.s.）；MemLens 多问画面细节（D-035） |

六个假设里，完全成立的只有 H5，H1、H2 各成立一半。被否证的那几条同样说明了问题：

- **"想多深"能挣的很少**（H1 后半、H2）；
- **会用工具的模型自己决定检索也很好**（H3）；
- **有效期标签在答题准确率上没有可测的收益**（H4）。它的价值在于能说清"什么时候、为什么变了"，例如 N8 演示里预算从 $120 改到 $180。

## 10. 局限与教训

### 10.1 局限

- **判分只用一个模型。** qwen3.8-max 与主回答模型不同家族（D-008），判分模板逐字照搬官方；但人工复核的错题里有 2 / 38（LongMemEval）、4 / 40（LoCoMo）、5 / 40（MemLens）是判分过严，绝对准确率偏保守。同一判分下方法之间的比较不受影响。
- **每个组合只跑一次。** 温度 0 下回答仍会因证据的细微差别而翻转（N7：585 题里 L2 救回 45 题、又弄错 17 题），配对检验能分辨的差异大约在 3–5 个点以上。
- **MemLens 测试集在 N6 已经报告过一次**（那时的方法也是事先定的，D-048）；N9 的 MemLens 数字与 N6 有 ±1–3 题的出入：N6 的 32K、128K 两个运行同时进行，完全相同的请求并发时谁先写进缓存不确定（查到 1 次判分、3 个 L2 查询计划不同）。"可复现"指从缓存重放逐字一致，从零重跑会有这个量级的波动。
- **控制器只在开发集的 585 道题上训练**，跨数据集不能零样本迁移（N7）。测试集上发现三个问题，按 D-048 只记录、不回头改：
  - MemLens 上门控对指代图片的问题漏判（§8.3）；
  - 看图增益相加后截断，L1 + 看图与 L2 + 看图打平（§5.3）；
  - "各档准确率"按主回答模型标定，换了回答模型就不准（§6）。
- **标准答案有噪声。** 人工抽查的错题里，LoCoMo 有 10 / 40 是标准答案有误或推不出（时间题 7 道里占 5 道），MemLens 有 2 / 40 与会话日期矛盾。这些题没有剔除。
- **大模型一档没有跑。** deepseek-v4-pro 那一档因 DeepSeek 账户余额不足没有跑，H3 只覆盖小、中两档。
- **数据集都是英文的**，中文对话没有评测；小模型（qwen3.6-35b-a3b）的价格按 OpenRouter 的参考价记（D-049）。
- **运行中断。** 失败的请求不留下任何结果，补跑与一次跑完等价。中断有三次：
  - DeepSeek 账户余额在 LoCoMo 测试集跑到约四分之三时用完，之后的请求全部失败（不进缓存），充值后用同样的配置续跑。
  - qwen3.6-35b-a3b 的调用限额很紧，8 路并发时约三分之一的请求被限流，降到 2 路补跑。
  - test400 里有一个会话，qwen3.8-flash 抽取时生成失控，三个小时里重试 5 次都超时（每次 4 个请求、各等 120 秒）；这道题因此最后才跑完。超时与内容审核一样，本应换备用模型：为此给结构化输出加了超时回退（D-050）。加了回退之后重建，qwen 第一次请求就正常返回了，回退没有触发。

### 10.2 教训

1. **先把写入和读法做好，再做路由。** 最大的收益来自写入路径（LongMemEval +9 个点）和"先记笔记再回答"（LoCoMo 上 L1 +3.1 个点、比任何路由都划算）。控制器的价值在"要不要想起"（混合流省 41%），没有提高纯记忆题的准确率。如果重来，会更早把 L1 的默认读法改成先记笔记。
2. **标签与评估都要防"回答的随机翻转"。**
   - 事后理想路由与固定档位的差距，大部分是翻转。
   - N7 用推理类型作中介标签，开发集的估计在测试集上复现了（81.2% → 81.6%）。
   - 补检索在开发集上的 +4 / −0 在测试集上没有复现（+2 / −3），是同一个教训。
3. **冻结的测试集换来可信的数字，代价是发现的问题不能回头修。** MemLens 上的看图增益饱和，本可以在 N7 发现：只要把各动作的预测成功率按数据集画出来，就能看到两档同时被截成 1.0。
4. **回答模型的能力是一个会变的参数。** 控制器的"各档准确率"要随回答模型标定；"让模型自己检索"好不好，取决于这个模型会不会用工具。部署时控制器要能用少量在线标注重新标定，N7 里 20 条目标数据就补回了跨数据集的迁移。
5. **本地缓存让评测可复现、可审计。** 请求逐字相同才命中缓存，所以控制器的真实运行能与离线重放逐题核对；失败的请求不进缓存，所以余额用完、限流、超时之后续跑，与一次跑完等价。
6. **先审一遍数据集。** 绝对准确率与他人的数字比较时要谨慎：LoCoMo 的时间题有不少标准答案本身就错，MemLens 有叙述顺序与会话日期矛盾的题。

## 11. 复现

所有结果都可以用 `scripts/reproduce.py` 重新生成（固定的运行名与方法列表；有本地缓存时只重新生成报告与图，几乎不花钱）：

```bash
uv run python scripts/reproduce.py --dry-run     # 列出全部步骤
uv run python scripts/reproduce.py --only N9     # 只复现最终评测
```

N2、N3 的数字用的是旧向量模型 text-embedding-v4，复现脚本会自动切换；N8 的上下文布局实验关掉了本地缓存、每次真实调用，不在复现脚本里；N9 的大模型回答档还没有跑过，是可选步骤（`--with-optional`）。
