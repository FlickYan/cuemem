- [x] 评测提速：记忆空间落盘复用、纯检索调参脚本（零 LLM 成本）、相同请求合并、续跑一致性检查（D-028）
- [x] DeepSeek 错峰调度（D-024）

**验收结果**（qwen3.7-text-embedding）：
- dev100 端到端：B4 83%，与 ORACLE 持平；每题输入 4,973 tokens、名义成本 $0.0016，是检索类方法里最低的。对 B2（76%）+9 / −2（p = 0.065），对 B2F（80%）+6 / −3（p = 0.51）。dev100 已接近饱和；
- 跨数据集（LoCoMo 前 3 段对话，385 题）：B4 84.9%，对 B2F 78.7% 配对 p = 0.001，对 B2 75.6% p < 0.001；与 ORACLE 87.5% 不显著（p = 0.24）；
- 纯检索（dev100，固定前 10 轮）：发言召回（任一）B2 93.6% → L1 100%；端到端报告里"检索未命中"的错题 B2 6 → B4 0；
- 延迟：L1 检索 p50 99 ms、p95 132 ms，含一次不走缓存的查询向量化（p95 113 ms）；本地检索与融合 p95 20 ms。目标 p95 ≤ 300 ms，达到；
- 消融：按 token 预算打包是最大的杠杆（LoCoMo 上固定 10 轮只有 77.1%，p < 0.001；这一项是看过 LoCoMo 结果后加的，LoCoMo 对它不是独立检验，见 D-029）；去掉相对时间标注 dev100 −4（p = 0.22）；时间区间加分、BM25 在两个数据集上都不显著。

**要点**：为什么 RRF 会把强命中挤下去（模态内取最大、模态间才 RRF）；为什么固定条数在不同数据集上差十几倍上下文（按 token 预算打包）；换一个更好的向量模型胜过所有检索技巧，选型要用目标指标说话；BM25 的价值取决于 dense 有多强；开发集饱和之后，价值要用成本和第二个数据集来证明。

### N5 L2 深度检索（L，已完成，2026-10-12）

- [x] 查询规划：答案类型、是否需要穷尽、子查询、时间区间（规则优先，模型换算为补充并校验）、目标实体；失败时退回规则版计划
- [x] 多查询召回：每个子查询各做一遍 L1 打分，按"取最好名次"融合（名次分求和的 RRF 没有收益，D-030）
- [x] 实体链接 + 个性化 PageRank 图扩散（scipy.sparse）：三部图 + 提及边 + 相似事实边，去掉枢纽实体；dev100 上没有提高召回，默认关闭（D-031）
- [x] 迭代检索 + 充分性检查（最多 2 次补检索）
- [x] 笔记式阅读（先记笔记再回答，按计划给阅读提示）；带引用回答；日期计算工具（`date_diff`）；误拒答统计
- [x] `memory_search` 工具接口与基线 B3（模型自主检索，ReAct）
- [x] 规则版控制器（B6r，N7 的基线）
- [x] 复议 BM25（D-026 修订）：qwen3.7 下在各种预算、有无重排时都不提高召回，L1、L2 默认去掉；重排（qwen3-rerank）没有提高预算内的召回，不采用（D-032）
- [x] 评测：L2 的检索过程统计（规划、检查、补检索、证据 tokens）；同一段对话的题也并行回答（LoCoMo 只有 3 段对话）

**验收结果**：
- dev100：B5 89%（L1 81%、B4 83%、ORACLE 83%），每题 $0.0034、3.25 次 LLM 调用。多会话题 54% → 79%（对 B4 +8 / −2，**p = 0.11，未达显著**），时间推理题 80% → 84%（+1 / −0）。对当前 L1 +11 / −3（p = 0.057）。
- LoCoMo 385 题（没有参与任何调参）：B5 89.1%（L1 86.2%、B4 84.9%、ORACLE 87.5%），对 B4 +27 / −11（**p = 0.014**），对当前 L1 +21 / −10（p = 0.071）；多跳 80% → 88%（+10 / −4），时间 88% → 93%（+5 / −0，p = 0.06）。
- 验收结论：两个数据集上多会话 / 多跳与时间题的方向一致，但分题型都没到 p < 0.05，**验收标准没有完全达到**；以 N9 的 test400 与 LoCoMo 其余对话为准。
- 消融：最大的杠杆是笔记式阅读（dev100 去掉后 −8，p = 0.077；L1 加上笔记 dev100 86%、LoCoMo 88.6%）；补检索 −4（+4 / −0）；查询规划 −1、图扩散 −1，都不显著。LoCoMo 上加图扩散 90.1%（对 B5 +4，p = 0.39），默认值不变，N9 复测。
- 规则版控制器 B6r：dev100 88%、每题 $0.0028（62% 的题走 L2），对 L1 +8 / −1（p = 0.039），比 always-L2 便宜 18%、只少 1 题；但在 LoCoMo 上只有 8% 的题触发规则，等于 L1（86.0%）。理想路由（事后选最便宜且答对的一档）两个数据集都约 92%、成本接近 L1，是 N7 的空间。B3 模型自主检索 dev100 86%、$0.0033（按 DeepSeek 前缀缓存价约 $0.0020）。

**要点**：为什么多查询融合不能用 RRF（共识 vs 并集）；为什么 PPR 在个人记忆上不灵（图是"一个人连着所有事"的星形）；阅读方式比检索更重要（同样的证据，记笔记 +8）；什么时候该停止检索（充分性检查、补检索只在约四分之一的题上触发）；规则控制器在一个数据集上拿到大部分收益、换一个数据集就失灵，可学习控制器要靠检索探针特征跨数据集泛化。
