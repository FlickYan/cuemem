依赖关系：N1 → N2 → N3 → N4 → N5 → N6 → N7；N8 可在 N5 之后并行推进；N9、N10 收尾。

为什么多模态在控制器之前：
- 多模态是本项目的差异点，图片记忆的结果越早出来越好；
- 控制器要在"所有可选动作"之间做决策。先有再感知，控制器从一开始就能决定要不要回看原图，不用事后返工。

风险：核心创新（控制器）排在第 6–7 周。应对办法是 N5 结束时先放一个规则版控制器作为基线，N7 再做可学习版本。

### N1 工程骨架与基础设施（M，已完成，2026-10-12）

**目标**：后面所有节点都建立在一个干净、可测试、可复现的底座上。

- [x] `git init`、`.gitignore`、目录结构（见设计文档 §9.4）
- [x] `uv` + Python 3.12 + `pyproject.toml`；`ruff`、`mypy`、`pytest`、`pre-commit`
- [x] 配置系统：YAML 默认值 + 环境变量覆盖（深度合并）+ `.env` 中的 API Key；按角色配置模型
- [x] LLM 客户端：OpenAI 兼容接口同时接 DeepSeek 与通义；关闭思考模式；按供应商限流；**SQLite 响应缓存**（含只读模式）；**token 与成本记账**；结构化输出（JSON 模式 + Schema + 校验失败重试）
- [x] 向量服务：通义原生接口一次取 dense + sparse；内容哈希缓存；离线哈希向量器（测试与无 Key 演示）

- [x] 端到端冒烟：示例对话写入 + 5 个问题，答对 4 个

### N2 评测框架与基线（M）

**目标**：先能"量"，再去"优化"。之后的每个改动都用同一把尺子衡量。

- [ ] 数据加载：LongMemEval_S（含证据标注）、LoCoMo → 统一的 `Sample` 结构（MemLens 在 N6 接入）
- [ ] 数据划分：LongMemEval_S 按五种能力分层抽 100 题做开发集，其余只用于最终评测
- [ ] 统一 runner：写入 → 提问 → 判分；断点续跑；线程池并发（受供应商限流约束）
- [ ] Judge：采用官方评测 prompt；judge 固定为 qwen3.8-max；人工抽检 50 条看一致性
- [ ] 指标：分能力准确率、Recall@k、token、LLM 调用次数、分阶段延迟 p50 / p95、名义成本；bootstrap 置信区间
- [ ] 基线：B0 无记忆、B1 全上下文、B2 Naive RAG（即 N1 的 `ask`）
- [ ] 报告生成：一条命令产出 Markdown 结果表与图

**验收**：一条命令复现结果表；明确知道跑一次开发集评测要花多少钱、多少时间。
**要点**：评测先行；为什么不同论文的数字不能直接比较；LLM judge 的偏差与对策。

### N3 写入路径：结构化、带有效期的记忆（L）

- [ ] 数据模型：Turn / Episode / Entity / Fact / MediaItem
- [ ] 抽取：一次 LLM 调用输出事实、实体、事件时间、重要度（结构化输出）；qwen3.8-flash 与 deepseek-flash 抽样比对
- [ ] 实体消歧：别名精确匹配 + 向量相似度，灰区才调用 LLM 确认
- [ ] 事实对账：ADD / SUPERSEDE / MERGE / NOOP；双时间轴有效期；谓词基数表（单值 / 多值）
- [ ] 会话摘要、事实增强键、核心记忆（用户画像）更新
- [ ] 异步任务：幂等、可重放；按溯源级联删除（forget）
- [ ] 记忆检查器 CLI：事实时间线、实体、来源
- [ ] 测试：知识更新、冲突、历史状态查询、遗忘等场景

**验收**：场景单测全部通过；开发集"知识更新""信息抽取"类别相对 B2 有提升；给出写入成本（每千轮 token）。
**要点**：写时智能与读时智能；双时间轴；为什么"失效而不删除"；幂等与可重放；被遗忘权。

### N4 L1 快速召回（M）

- [ ] 统一多粒度索引：事实 / 轮次 / 会话摘要 /（预留）图片描述
- [ ] 混合检索：dense + sparse → RRF 融合（比较 text-embedding-v4 词项权重与 BM25；处理角色标签、标点与数字切分）
- [ ] 向量模型对比：text-embedding-v4 vs qwen3.7-text-embedding（开发集 Recall@k，D-014）
- [ ] 回归用例：示例对话的 5 个问题（N1 时 B2 答对 4 个，"第一次提到旅行"因检索失败答错）
- [ ] 时间表达解析（中英文，相对问题发生时间）→ 过滤或加权
- [ ] 打分重排：相关性、新近性（按查询类型开关）、重要度、有效性；可选模型重排
- [ ] 时间感知的上下文打包：绝对日期 + 相对时间 + 有效状态

**验收**：开发集 Recall@k 与准确率超过 B2；L1 的 p95 延迟在目标内（暂定 300ms，含一次向量接口调用）。
**要点**：RRF 为什么有效；dense 与 sparse 怎样互补；时间感知打包这类便宜但有效的技巧。

### N5 L2 深度检索（L）

- [ ] 查询规划：子问题、时间约束（换算为绝对区间）、目标实体、答案类型
- [ ] 实体链接 + 个性化 PageRank 图扩散（scipy.sparse 实现）
- [ ] 迭代检索 + 充分性检查（最多 R 轮）
- [ ] 拒答策略；带引用回答；日期计算工具
- [ ] `memory_search` 工具接口（供 reader 主动调用，也用于 N7 的 B3 基线）
- [ ] 规则版控制器（N7 的基线）

**验收**：开发集"多会话推理""时间推理"类别显著提升；统计每题平均 LLM 调用次数与 token。
**要点**：PPR 为什么适合多跳；迭代检索怎么停；拒答和幻觉的关系。

### N6 多模态记忆（L）

- [ ] 图片写入：内容寻址存储、多模态向量（QwenCloud 的 tongyi-embedding-vision-plus）、上下文感知描述 + OCR、实体绑定
- [ ] 跨模态检索：描述路 + 视觉向量路 + 以图搜图，RRF 融合
- [ ] 再感知 reader：deepseek-flash 或 qwen3-vl-plus 直接看原图
- [ ] 接入 MemLens（195 题记忆智能体子集；32K 与 128K 两档长度）
- [ ] 对比：仅描述 vs 再感知 vs 长上下文直接看图；上下文感知描述 vs 孤立描述（若平台支持，再加图文融合向量）
- [ ] ☆ 视频：关键帧 + 语音转写 → 片段级情景记忆（贴近短视频场景）

**验收**：MemLens 子集结果；验证或否证 H5、H6；图片 token 成本统计。
**要点**：存储时压缩与回答时再感知；图片的含义依赖对话上下文；与字节 Seed 的 M3-Agent 的异同。

### N7 检索控制器（核心，L）

- [ ] 探针特征：检索分数分布、查询线索（含视觉细节词）、实体与时间命中、对话状态
- [ ] 离线全信息标注：每题分别跑 L0 / L1 / L2（及再感知开 / 关）并判分，记录正确性与成本
- [ ] 策略模型：规则基线 → LR / LightGBM（概率校准）→ 效用决策 + λ 旋钮
- [ ] 反应式升级：L1 证据不足 → L2；比较"仅预测 / 仅反应 / 两者结合"
- [ ] Mixed-Stream：记忆相关与无关查询混合，评测"该不该想起"
- [ ] 基线 B3：模型自主检索（ReAct + `memory_search`）；零样本 LLM 路由器
- [ ] 分析：帕累托曲线、特征重要性与消融、跨数据集泛化、跨底座稳定性
- [ ] ☆ 上下文 bandit 在线学习仿真（部分反馈，LinUCB / Thompson Sampling）

**验收**：产出帕累托图；验证或否证 H1–H3，无论结果如何都如实报告。
**要点**：为什么不让 LLM 自己决定；标签怎么来；λ 作为业务旋钮；与 Adaptive-RAG、Agent Zero Memory 的区别。

### N8 Agent Runtime 与 Demo（M）

- [ ] 自研 agent loop：上下文分区预算、稳定前缀（利于 prompt cache）、工具调用

**要点**：上下文工程；可解释的记忆；隐私控制；和内容电商客服、导购场景的结合。
